## 0. 왜 순서가 중요한가

세 가지가 서로를 막는다.

- 스크린샷은 **배포된 화면**에서 찍어야 한다. 로컬 시뮬레이션 화면을 제출하면 라이브에 없는
  것을 제출하는 것이 된다.
- 제공자 동의 화면 스크린샷은 **OAuth 가 켜진 뒤**에만 찍을 수 있다.
- OAuth 를 켜는 것은 **공개 계정 기능을 여는 것**이라 그 앞의 조건이 따로 있다.

그래서 아래 순서를 건너뛰지 않는다.

## 2. 배포 직후 브라우저 확인 (OAuth 없이)

OAuth 가 꺼져 있어도 여기까지는 라이브에서 확인된다.

1. 첫 진입에 **가입 / 로그인 / 둘러보기 세 갈래**가 보인다.
2. 게이트 안에 **방침·약관 링크**가 있다.
3. 「가입하기」를 누르면 약관을 불러오는 동안 **로딩 문구**가 뜨고, 뜬 뒤 화면이 **맨 위에서**
   시작한다(중간부터 보이면 안 된다).
4. 체크 전에는 제공자 버튼이 **눌리지 않는다.** 두 개를 다 켜야 열린다.
5. `/api/ready` 가 200 이고 `db`·`ledgerBound`·`ledger` 가 `true` 다. `cleanupStale`·`cleanupAlert` 는 `false` 다.
6. `/privacy.html` · `/policies/` 가 열린다.
7. 콘솔에 오류가 없다.

⚠️ **제공자가 설정되지 않았으면** 가입 화면은 「지금은 가입을 준비 중이에요」 또는
「서버에 연결할 수 없어요」라고 말하고 **되지 않는 버튼을 그리지 않는다.** 그 문구가 보이는 것이
정상이다 — 그 상태로 스크린샷 4번(제공자 선택)을 찍을 수는 없다.

## 4. 이 runbook 이 금지하는 것

- 배포 전에 콘솔을 고치는 것
- 라이브에 없는 화면을 설명문에 적는 것
- 로컬 시뮬레이션 화면을 스크린샷으로 제출하는 것
- 시크릿 값을 명령 출력·로그·커밋·이 문서에 남기는 것
- `네이버검수-캡처/` 를 열거나 옮기거나 stage 하는 것 — **사용자 파일이다**
- 「검수 통과 보장」·「법적 위험 없음」·「연령 인증 완료」 류의 표현
