   생겼을 때 검사 하나가 조용히 빠지는 길이 없나.
3. **`PWA3-4`~`PWA3-6` 결정 자체**(`54a4614`) — 사용자가 권고와 다른 안을 골랐고, 그 선택이
   **아직 확인 못 한 조건**(게이트 `R9`) 위에 선다는 것을 문서가 정확히 적고 있나.
4. **이번에 반영한 단계표 수정 여섯**(`77fb8fe`) — 특히 **`R9` 를 게이트로 세운 것**이 맞나,
   기한(「PWA-3 §4 를 쓰기 전」)이 실제로 그 자리가 맞나.
5. **이 인계서 자신**(`docs/SESSION_HANDOFF_2026-09-07.md`) — 원본을 가리키기만 해야 할 자리에
   **상태를 복제해 두고 낡을 씨앗을 심지 않았나.** ⚠️ **실제로 한 번 그랬다** — 검토 대상 커밋을
   손으로 나열했다가 이 문서를 쓰는 커밋 자신이 빠졌고, 그래서 명령으로 바꿨다.

⚠️ **Codex 도 틀린다** — 지적을 그대로 받아 적지 말고 **재현하거나 근거를 확인한 뒤** 반영하고,
반영하지 않은 지적은 **이유와 함께** 남긴다. **지적이 0건이면 「0건이었다」를 보고에 적는다.**

### 2️⃣ 게이트 `R9` — 사용자에게 물어야 하는 것

**제공자 콘솔이 복귀 주소를 하나 더 받는가.** ⛔ **Claude 는 그 콘솔을 못 연다**(브라우저 도구가
네이버 개발자센터 도메인을 거부한다) — **사용자만 할 수 있다.**

- **왜 지금인가**: `PWA3-4`(앱 전용 복귀 문) **전체가 이 답 위에 선다.** 못 받으면 다리 설계를
  처음부터 다시 고른다. ⛔ **재심사 회차까지 미루면 설계를 다 짜 놓고 뒤집게 된다.**
- **시점은 사용자가 정한다** — 지금 / 코드 짜기 전 / APP-2.
- ⛔ **답이 없는 채로 앱 전용 라우트를 라우트 표에 올리지 않는다.**

### 3️⃣ PWA-3 §3 에 열려 있는 여섯을 닫는다 — ⛔ **§4 보다 먼저**

`docs/PWA3_SHARED_API_DESIGN.md` §3 의 **3~8번**이다. ⛔ **개수와 내용의 원본은 그 문서이고,
여기 옮겨 적은 것은 길잡이다.** 요지만: 본인확인 실패·중단 시 무엇을 남기나 · 생년월일 오기 정정 ·
새 스키마에서 탈퇴가 무엇을 지우고 남기나 · 기관이 바뀌어 식별값이 어긋날 때 기존 회원 ·
별명 금칙어 목록의 출처 · 제공자별 연결 해제가 실제로 있는가.

⛔ **여섯 다 사용자 결정이다**(절대규칙 2). 선택지마다 **장단점·위험·비용과 권고안까지** 내고
질문한다. ⛔ **채팅에 먼저 쓰지 않는다** — **파일에 먼저 쓰고** `node scripts/test-claims.mjs` 를
통과시킨 뒤 보낸다. 「쉬운 말」 칸에 기술 용어·경로·대문자 이름이 있으면 검사가 실패시킨다.
⚠️ **지난번에 셋 다 「이해하기 쉽게 다시 설명해」로 돌아왔다** — **비유를 도입부에만 쓰고 정작
고르는 표는 기술 용어로 냈기 때문**이다. 표까지 쉬운 말로 쓴다.

### 4️⃣ 그 뒤에 §4~§10 을 쓴다

API 계약 · DB 스키마 · 오류 코드 · 상태 전이 · 위협 모델 · migration 순서 · 테스트 명세.
⛔ **위 셋이 닫히기 전에 쓰면 정해지지 않은 것을 정해진 것처럼 적게 된다** — 이 저장소가
여러 번 겪은 실수다. **첫 항목 둘은 이미 정해져 있다**(§3 의 갈리는 자리 둘 · `docs/ROADMAP.md` PWA-3).

### 5️⃣ 코드는 그 다음이다

⛔ **지금 쓰면 검토도 결정도 없이 짜는 것이 된다.** 코드를 건드리는 순간 **`npm test` 전체와
돌연변이 전수 실행**을 돌린다 — 이번 회차는 코드를 안 건드려서 문서 검사 셋만 돌렸다.

### ⛔ 어느 단계에서도 하지 않는 것

- **Git push** · 배포 · 원격 데이터베이스 실행 · 시크릿 변경 · 캐시 퍼지 · DNS 변경 — **전부 승인 대상**이다.
  ⚠️ 현재 브랜치는 `cf-pages` 이고 **push 하지 않았다.** ⛔ **앞선 커밋 수를 여기 적지 않는다** —
  `git log --oneline dab6500..HEAD` 가 미검토분을, `git status` 가 작업 트리를 답한다.
- 사용자를 대신해 제공자 콘솔·개발자 계정·결제에 손대는 것.
- 확인하지 않은 것을 확인한 것처럼 적는 것. ⚠️ **이 저장소에서 가장 자주 뒤집힌 실수다** —
  근거표에 실측이면 **명령과 날짜**, 원문이면 **주소와 날짜**를 함께 적는다.
