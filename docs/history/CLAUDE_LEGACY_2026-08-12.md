**설치 버튼은 두 갈래다.** 크롬은 `beforeinstallprompt` 를 가로채(기본 배너를 막고) 우리 버튼에서
설치 대화상자를 연다. **iOS 사파리엔 그 이벤트가 아예 없어서** 버튼이 대화상자 대신 안내 문구를 편다
(공유 → 홈 화면에 추가). 그래서 iOS 판정이 필요한데 **iPadOS 13+ 는 UA 를 맥으로 보낸다** —
`maxTouchPoints` 를 같이 안 보면 아이패드를 전부 놓친다.
- `setupInstall()` 은 **`main()` 첫 줄**에서 부른다. 사전 로드(`await`)를 기다리면 그 사이 날아온
  `beforeinstallprompt` 를 놓쳐 버튼이 영영 안 뜬다. 최상위에 두지 않는 이유는 함정 13.
- 이미 설치해 앱으로 열었으면(`display-mode: standalone`) 버튼을 아예 안 만든다.

**오프라인은 두 번 방문해야 되던 상태였다.** SW 의 런타임 캐시(`fetch` 핸들러)는 **첫 로드엔 안 돈다** —
그때 SW 가 아직 페이지를 제어하지 않기 때문. 그래서 선캐시 `ASSETS` 에 데이터 JSON 4개를 넣었다.
설치 직후 지하철에 들어가면 사전이 통째로 없던 것이 증상이었다.

  본 적 있는 그림만 런타임 캐시로 남는다. 수형 **설명 텍스트**는 오프라인에서도 나온다.

### 5b — 예산이 잡히면 (지금은 손대지 않는다)
| 항목 | 상태 |
|---|---|
| `.nojekyll` (Pages 가 `.well-known` 같은 점 폴더를 서빙하게) | ✅ 이미 있음 |
| Bubblewrap init/build (JDK 17 · Android SDK ~1GB 내려받음) | ⬜ |
| `.well-known/assetlinks.json` | ⬜ **키스토어 SHA-256 이 나온 뒤에.** 미리 넣으면 틀린 지문이 박힌다 |
| Play 개발자 등록 $25 · 스토어 등록 정보 | ⬜ 사람 몫 |
| 결제(Play Billing) — `requestPro()` 한 곳에 격리돼 있음 | ⬜ 백엔드 합의 필요(볼트 「안 할 것」) |

⚠️ 키스토어 비밀번호는 사람이 정하고 사람이 보관한다. **잃어버리면 앱 업데이트가 영영 불가.**

아이콘 PNG 를 다시 만들 때:
```bash
CH="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
"$CH" --headless --disable-gpu --hide-scrollbars --force-device-scale-factor=1 \
  --window-size=512,512 --screenshot="icons/icon-512.png" "file://$PWD/icons/icon.svg"
sips -z 192 192 icons/icon-512.png --out icons/icon-192.png   # 크롬으로 두 번 찍지 말 것 ↓
```
`rsvg-convert`·ImageMagick 은 이 맥에 없다. `sips` 는 SVG 를 **못 읽지만** PNG 축소는 된다.
- ⚠️ **크롬 창 크기로 192 를 찍으면 축소가 아니라 잘라내기다.** `icon.svg` 에 `width="512"` 가
  박혀 있어 192 창은 좌측 상단 192px 만 담는다 — 거긴 배경뿐이라 **빈 사각형이 나온다.**
  옛 `for s in 512 192` 루프가 이걸 저질렀고, `icon-192.png` 는 만들어진 날부터 빈 코랄 사각형이었다.
  `apple-touch-icon` 이 이 파일이라 **아이폰 홈 화면 아이콘이 통째로 비어 있었다.**
  512 한 장만 찍고 `sips` 로 줄인다.
- 아이콘 그림은 **헤더의 마스코트**(쉿 하는 얼굴)다. `index.html` 의 `<symbol id="mascot">` 과 같은
  도형을 `icon.svg` 가 베껴 갖고 있다 — 아이콘은 홀로 서는 파일이라 `<use>` 로 못 부른다.
  마스코트를 고치면 `icon.svg` 도 고치고 PNG 를 다시 렌더할 것.

## 📅 매일 100건 — 부품 수형 고르기 (진행 중)

- **고르는 법**: 합성 동작은 부품을 `… 다음,` 으로 잇는다. `--todo` 가 그 조각을 갈라 **「이 자리 동작」**
  으로 보여주므로, 그 한 줄과 후보 설명을 비교하면 된다. 손 그림을 볼 필요가 없다 — 문자열 비교다.
  ⚠️ "통째로 들어있는 걸 고르라"는 규칙은 **여기선 안 통한다.** 통째로 들어있는 건 CSV 가 이미 다 처리했고,
  남은 건 정의상 안 들어있는 것들이다. 표현이 조금씩 달라서 **더 가까운 쪽**을 고르는 일이다.
- **「닮음」 점수는 줄 세우기일 뿐 정답이 아니다.** 글자 2-gram 겹침이라 1등이 틀릴 수 있다
  (`튀르키예 = 달 + 별` 의 '달'은 표제어 `일개월` 이 아니라 `월` 이 맞다). 눈으로 확인하고 고른다.
  임계값을 두고 자동으로 못박지 않는 이유도 같다 — 임계값은 판단이고 판단은 사람 몫이다.
- **그림 있는 후보가 1개뿐인 자리(542)는 기본으로 건너뛴다.** 나머지 후보가 조사·이형태라 화면에 뜨지도

- **유튜브는 다른 축을 본다.** 영상은 *이 합성이 실제로 쓰는 표현인가*(`verify.mjs --add`)를 확인하지,
  *부품이 어느 수형인가*(`--pin`)를 정해주지 않는다. 게다가 결합정보 표제어는 `판무관`·`아당안지` 처럼
  강의 영상이 아예 없는 말이 많다. **영상은 사용자가 실제로 칠 만한 일상어에 쓴다**(잘자·보고싶다처럼).

### 활용 규칙 6개 — 2026-08-08 (측정하고 넣었다)
일상어 160개를 실제로 쳐보니 **`일어나` → `일어`(일본어) + 지화 `나`** 가 떴다. ⛔ 위반이라 고쳤다.
넣은 규칙: 르-불규칙(몰라→모르다) · 과거 았/었(화났어→화나다, 알았어→알다) · 부사 -이/-히(많이→많다,
조용히→조용하다) · 어간+다(일어나→일어나다) · 돼→되다.

**함정 23 이 요구하는 측정을 먼저 했다.** 표제어·별칭 전부 + 일상어 + 문장 **15,616 입력**을 규칙
전/후로 대조 → 달라진 것 30건, **지화가 늘어난 입력 0**. 그 30건 중 둘이 규칙을 좁히게 만들었다:

- **음절을 통째로 떼는 과거 규칙이 `지냈어`를 `지다`(패배)로 만들었다.** `지내다`는 사전에 아예 없어서
  조회로 안 걸러지고, 지화로 떨어지던 말이 **틀린 수어로 단정**된다. → 그 갈래는 그 글자가 **정확히
  았/었/였**일 때만 쓴다(초성이 있으면 그 자음은 어간의 것이다).
- **후보가 1글자 `"다"` 로 떨어져 1글자 표제어 `다`(=모두)에 걸렸다**(`재밌어` → 지화'재' + [모두]).
  `matchSentence` 의 1글자 가드는 **부분 문자열 길이만 보고 활용 후보는 안 본다** — 함정 16 을
  우회하는 구멍이었다. → `deconjugate` 가 1글자 후보를 버린다.

**알고 남긴 것 두 가지:**
1. `안돼 하지마` → `[안되다]` + 지화'마'. 어미 목록의 `하지` 가 별칭 `하지 마`([그만])의 앞부분을
   먹는다. **1:1 맞바꿈**이다(전에는 안돼가 지화, 하지마가 정답이었다).
   ⚠️ 어미를 삼키기 전에 "여기서 다음 말이 시작하나"를 묻는 안을 **재보고 버렸다** — 이건 고치지만
   맞던 것 3건을 깬다: `감사합니다` → [감사합니다]+[거행] 카드 두 장, `기다려` → [다리미질],
   `내가` → [해내다]. 어미와 표제어가 겹치는 게 흔한 일이라 1:3 이었다. **다시 시도하려면 이 셋부터 재라.**
2. `잘 지냈어` → 지화'잘지' + `[내다]`. `지냈어`가 사전에 없어 조각(`냈어`)이 매칭된다.
   활용 규칙은 **낱말 끝**에서만 뜻이 있는데 `norm()` 이 공백을 지워 낱말 경계가 사라진 뒤라 구분을 못 한다.
   경계를 살리려 해도 `conjugationNormalize` 가 길이를 바꿔서(합니다→하다) 인덱스가 어긋난다.

  pro 가 된다 — 그때 화면이 「마스터」와 「프로」를 구분해 말하려면 이름이 둘이어야 한다.
- 둘 다 **응답에만 얹고 KV 레코드에는 안 넣는다.** 넣으면 굳어서, 목록에서 빼도 옛 레코드가 계속
  마스터라고 말한다. 판단은 언제나 지금의 `MASTER_UIDS` 가 한다.
- 앱 쪽은 `setEntitlement()` 한 곳(`js/app.js`)이 받고 로컬에도 적는다 — 서버 응답을 기다리는 동안과
  오프라인에서 이름이 '무료'로 깜빡이지 않게. **오프라인이면 손대지 않는다.**
- **로그아웃하면 끈다.** 계정에 달린 값이라 계정을 놓으면 같이 놓아야 한다 — 안 끄면 로그아웃한
  기기가 계속 마스터로 보이고 다음 사람이 그대로 물려받는다.
- ⚠️ **`#master=<코드>` 방식은 만들었다가 지웠다**(같은 날). 로그인 없이 브라우저를 마스터로 만드는
  길이었는데, **링크가 새면 받은 사람도 마스터가 된다** — 마스터는 만든 사람 계정 하나여야 한다.
  대가로 「로그인 없이 둘러보기」 상태에서는 만든 사람도 벽에 걸린다. 되살릴 일이 생기면 커밋
  `1b68a90` 에 있다(시크릿 `MASTER_CODE` 도 같이 지웠다).
- **어느 계정이 내 것인지 가리는 법**: 이메일은 안 받으므로(방침대로 고유 번호만) 대조할 게 없다.
  → `wrangler d1 execute shhh-db --remote -y --command "SELECT id, provider, created_at FROM users"`
    에서 **`created_at` 이 가장 최근인 행**. 그 `id` 를 `MASTER_UIDS` 에 넣는다.
- ⚠️ **`MASTER_UIDS` 값이 2026-08-11 에 바뀌었다.** 예전엔 `kakao:1234567` 같은 제공자 번호였고
  지금은 내부 무작위 id 다. 옛 값을 그대로 두면 **아무도 마스터가 아닌 상태로 조용히 바뀐다**
  (기본값이 안전한 쪽이라 오류가 안 난다 — 그래서 눈치채기 어렵다).

### D1 이전 + 쿠키 세션 — 2026-08-11 (출시 전 보안 점검 3단계 · **현재 상태**)

**이 절이 저장소·세션에 관한 최신이다.** 아래 두 절(1단계·2단계)은 **KV 시절의 기록**이라
거기 적힌 `s:<uid>:<token>`·`KV.list`·Bearer 토큰은 지금 코드에 없다 — 왜 그렇게 했었고 무엇이
문제였는지를 읽는 용도로만 남긴다. 절차·롤백은 `docs/D1_MIGRATION.md`, 판정은 `docs/SECURITY_RELEASE_CHECKLIST.md`.

**옮긴 이유는 친구다.** 8/7 에 "저장하는 게 사용자→단어 배열 하나뿐이라 쿼리도 조인도 없다"며 KV 를
골랐는데, 그 판단은 **친구 기능이 생기는 순간 틀린 것이 됐다**. 관계는 두 사람에 걸친 데이터라 KV 로는
두 곳에 적어야 하고 트랜잭션이 없다 → 첫 쓰기만 성공하면 반쪽이 남았다. 처음엔 그 반쪽에서 남의
단어장이 안 열리게 **막는 코드를 붙였는데 그건 증상을 막은 것**이다. D1 에선 관계가 행 하나라
**반쪽이라는 상태가 존재하지 않고**, 그 방어 코드도 같이 사라졌다.

| 무엇 | KV 시절 | 지금 |
|---|---|---|
| 친구 관계 | 두 사람 레코드에 각각 | **`friendships` 행 하나** |
| 수락 · 끊기 | 두 번의 쓰기 | `UPDATE` · `DELETE` **각 한 문장** (`changes` 로 판정) |
| 계정 삭제 | 6번의 개별 삭제 | `DELETE FROM users` + **CASCADE** |
| 로그아웃 | `KV.list` 훑기(≤60초 창) | `session_version + 1` — **훑지 않으므로 창이 없다** |
| 세션 토큰 | `<b64u(uid)>.<무작위>`, localStorage | **완전 무작위**, HttpOnly 쿠키, DB엔 **SHA-256 만** |
| uid | `kakao:1234567` (친구·주소·토큰에 노출) | 무작위 32자. 제공자 번호는 `users` 행 안에만 |

- **쿠키와 D1 은 같은 커밋에 넣었다.** 쿠키만 먼저 나가면 지금 Bearer 라 **성립조차 안 하는 CSRF
  공격면을 새로 열고** 얻는 게 없다. `session_version` 이 D1 에 있어야 "모든 기기 로그아웃"이 즉시 든다.
  → 그래서 상태 변경 요청은 **`Origin` 을 본다**(`allowed()` 재사용). GET 은 안 본다 — 낯선 Origin 에는
    CORS 를 안 열어 줘서 응답을 못 읽는다.
- 쿠키 속성: `HttpOnly; Secure; SameSite=Lax; Path=/api`. `Path=/api` 라 정적 자산 요청엔 안 실린다.
- **네이버 갈래만은 세션 고정이 아직 성립한다.** `?code=…&state=…` 링크를 받은 사람의 앱이 남의 code 를
  대신 내밀면 서버가 그 브라우저에 **남의 계정 쿠키**를 심는다. 그래서 nonce 대조를 남겼고, 안 맞으면
  `apiLogoutRaw()` 로 **그 자리에서 세션을 끊는다** — 안 끊으면 화면은 로그아웃인데 서버는 로그인이다.
- **데이터는 안 옮겼다.** 이전 시점 KV 실측이 계정 1개·친구 0개라, 백필 스크립트보다 "다시 로그인 +
  기존 `#w=` 공유 링크"가 싸고 안전했다(새로 쓴 코드 0줄). **사용자가 늘면 이 선택지가 영영 닫힌다.**
  - 개인 복구 링크와 별명은 2026-08-12에 Git 제외 `CLAUDE.local.md`로 옮겼다.
- **KV 바인딩은 남겨 뒀다.** 롤백하면 옛 코드가 KV 를 읽어야 선다. D1 이 자리를 잡으면 같이 지운다.
- 테스트가 **가짜 KV(Map) → 진짜 SQL(`node:sqlite`)** 로 바뀌었다. Map 은 절대 실패하지 않고 즉시
  일관적이라, 이번에 재려던 것(제약·트랜잭션·`changes`)을 정확히 지우고 있었다. 43 → **75개**.
- 곁가지로 고친 것: 예외 로그가 `/friends/<uid>` 를 그대로 찍었다 → `pathTemplate()` 로 `:id`.
  **운영 로그가 "누가 누구와 친구인가"의 기록이 되던 자리**다(안 받기로 한 정보를 로그가 대신 모은다).

### 세션·삭제·본문 한도 — 2026-08-11 (출시 전 보안 점검 1단계 · **KV 시절 기록**)
코덱스 보고서를 직접 재본 결과에서 나온 것들. **가장 큰 구멍은 보고서에 없던 것**이었다.
- **로그인 시작(`/login/*`)이 인증 없이 KV 에 썼다.** 무료 플랜 KV 는 **하루 1,000 writes** 라
  `curl` 반복 1,000번이면 그날 남은 시간 동안 아무도 단어장을 저장하지 못한다. 계정도 도구도 필요 없다.
  → `state` 를 KV 에 넣지 않고 **HMAC 서명해서 들려 보낸다**(`makeState`, 시크릿 `STATE_KEY`).
    대가로 1회용 보장을 잃지만 `code` 쪽이 1회용이라 두 번째 교환은 제공자가 거부한다.
- **세션 키가 `s:<uid>:<token>` 으로 바뀌었다.** 토큰은 `<b64u(uid)>.<무작위>` 이고, 담긴 uid 는
  **주장일 뿐** — KV 에 그 키가 있어야 로그인으로 친다. uid 로 묶는 이유는 하나다:
  **로그아웃·탈퇴가 이 계정의 모든 기기에 들어야 하는데** 토큰만으로는 어느 계정인지 모른다.
  - 전에는 로그아웃이 `setAuth(null)` 뿐이라 KV 세션이 **180일을 더 살았다.** 한 번 샌 토큰이
    로그아웃 뒤에도 그대로 쓰였다.
  - 전에는 탈퇴가 현재 기기 토큰만 지워서, 다른 기기가 `myCode()` 로 초대 코드를,
    `PUT /book` 으로 단어장을 **되살렸다** — `privacy.html` 의 "그 자리에서 지워집니다"가 거짓이었다.
    문서를 고친 게 아니라 **코드를 문서에 맞췄다.**
  - ⚠️ KV `list` 는 최종 일관성이라 **방금 만든 세션이 목록에 없을 수 있다**(최대 60초).
- **본문 한도는 `Content-Length` 로 못 막는다.** 공격자는 그 헤더 없이(chunked) 보내면 그만이다.
  → `readBody()` 가 스트림을 읽으며 8KB 에서 끊는다. Node 의 `Request` 는 Content-Length 를
    안 붙이므로 **테스트가 저절로 chunked 경로를 잰다** — 헤더만 보는 구현이면 거기서 걸린다.
- 검사는 `test-friends.mjs` 21~27. 규칙을 되돌리면 실제로 실패하는 것까지 확인했다.

**실기기 확인(노트북 + 폰 PWA)에서 나온 것 둘.** 둘 다 서버가 아니라 **앱 쪽** 문제였다.
- **계정을 갈아 로그인하면 앞 계정 단어장이 뒷 계정 서버로 올라갔다.** 로그아웃이 로컬 단어장을
  남기는데(그건 맞다 — "이 기기에서 그만 보기"지 "지우기"가 아니다), 다음 로그인이 `firstLogin`
  이라 **합집합 병합**을 하기 때문이다. 한 기기를 두 사람이 쓰면 앞사람 단어장이 뒷사람 계정에 실린다.
  → `syncPlan` 에 `accountChanged` 를 넣어 **계정이 바뀌면 무조건 pull**. 계정 판정은 토큰 앞부분
    (`authUid()`)으로 한다 — 토큰이 `<b64u(uid)>.<무작위>` 라 서버에 안 물어도 안다.
  - **버려도 잃는 게 없다**: 담기는 `mayAddToBook()` 을 거치고 `mergeFromHash` 도 그렇다 —
    **로그인 없이 로컬 단어장이 생기는 길이 없다.** 첫 로그인(`shh-uid` 가 빈 값)은 종전대로
    합집합이라, 로그인 기능 이전에 담아둔 단어장은 그대로 살아난다.
  - `shh-uid` 는 **서버가 대답한 뒤에만** 적는다. 오프라인에서 적어 두면 다음에 온라인으로 들어올 때
    계정이 안 바뀐 것으로 보인다.
- **다른 기기에서 로그아웃해도 이 기기 화면은 로그인 상태로 남았다.** 서버는 제대로 끊었다
  (KV 에서 그 계정 세션 0개 확인). `apiCall` 이 401 에 `setAuth(null)` 만 하고 **화면을 다시 안 그려서**,
  담기를 눌러야 안 되는 걸 알 수 있었다.
  → `onAuthLost` 훅(authApi.js → auth.js). 데이터 계층이 화면을 직접 못 만지므로 알리기만 한다.
  - ⚠️ **즉시는 아니다.** 서버와 한 번 이야기해야 알 수 있어 앱을 다시 열거나 단어를 담을 때 반영된다.
    푸시는 5b 자리다. 네이버로 시험했을 땐 안 풀린 것처럼 보였고 카카오로 다시 하니 풀렸는데,
    **차이는 그 사이 앱이 서버를 불렀느냐뿐**이었다.
- **계정 삭제 안내문을 같이 고쳤다**(함정 51 — 한 곳을 고치면 그 값을 쓰는 옆 문구를 다시 본다).
  「이 폰에 담아둔 단어는 **그대로** 남습니다」가 두 곳에 있었는데, 계정 교체 시 병합을 끊은
  순간부터 **조건부**가 됐다. 「로그인이 풀려요」도 이제 **모든 기기에서** 풀린다.
  사용자가 화면을 보고 지적해서 알았다 — 코드를 고칠 때 그 코드를 설명하는 문장을 같이 찾지 않았다.
- **앱의 계정 삭제 경로를 실제로 눌러 검증했다**(구글 계정, 2026-08-11). KV 에 `b:`·`u:`·`c:`·`s:`
  어느 것도 남지 않았다 — `privacy.html` 의 삭제 문단이 사실임을 화면 경로로 확인한 것이다.

  | 유료벽 서버 판정 | 벽의 단위가 **손짓 수**라 서버가 사전을 알아야 한다. 결제를 붙일 때 함께 설계 |
  | 친구 관계 원자성 | Durable Object 이전. 사용자 둘짜리 앱에 과하다(코드 주석에 승급 조건 있음) |

### 출시 전 적대적 검토 2차 — 2026-08-11 (보고서를 재보고 고친 것 · **KV 시절 기록**)
외부 검토 보고서(High 6 · Medium 6 · Low 1, 판정 No-Go)를 **그대로 받지 않고 직접 쟀다**(함정 52).
절반은 사실이었고, 절반은 이 앱의 구조를 잘못 읽었다. 고친 것과 **일부러 안 고친 것**을 같이 남긴다.

| 지적 | 내 판정 | 한 일 |
|---|---|---|
| 세션 고정(`#login=` 무검증) | **사실 · 최우선** | nonce 결속(아래) |
| 로그아웃/탈퇴 뒤 세션 생존 | 절반 — 창은 ≤60초지, 180일이 아니다 | **누르는 그 기기의 토큰을 명시 삭제** |
| 친구·삭제 원자성 | 사실이나 KV 로는 못 없앤다 | 한도로 명시(승급은 Durable Object) |
| 레이트리밋 없음 | 수단이 틀렸다 | 친구 상한 50 · 외부 fetch 타임아웃 |
| 프로가 클라이언트 판정 | **출시 차단 아님** — 파는 물건이 없다 | 그대로. 결제 붙일 때 서버 판정 |
| 방침·설정 불일치 | **사실 · 출시 차단** | privacy.html · SETUP.md · 옛 배포 설정 정리 |
| no-store · Vary · 타임아웃 · 전역 예외 · 로그 | 사실 | 전부 반영 |
| 스키마 버전 필드 | YAGNI | 안 넣는다(필드 3개짜리 레코드다) |

- **세션 고정이 진짜 구멍이었다.** `#login=<토큰>` 은 **링크로 만들어 남에게 보낼 수 있는 문자열**인데
  앱이 무조건 받았다. 공격자가 자기 토큰 링크를 보내면 피해자가 **공격자 계정으로** 로그인되고,
  그 뒤 담는 단어와 별명이 공격자 계정에 쌓인다. 로그인 실패가 아니라 **성공**해 보이는 게 고약하다.
  → 앱이 로그인을 시작할 때 무작위 값(`shh-nonce`)을 적어 서버에 들려 보내고, 서버는 그걸 **state 에
    서명해 두었다가** 콜백에서 그대로 돌려준다. 앱은 적어 둔 값과 같을 때만 토큰을 받는다.
    공격자는 피해자 브라우저의 값을 모르므로 링크를 만들 수 없다.
  - **네이버 갈래에도 똑같이 필요하다.** `?code=…&state=…` 역시 링크로 보낼 수 있어서, 앱이 남의
    code 를 교환해 남의 계정으로 로그인한다. `/exchange` 가 `n` 을 같이 돌려주고 앱이 대조한다.
    한쪽만 막으면 공격자는 막힌 쪽을 안 쓴다.
  - ⚠️ **보고서가 권한 "HttpOnly 쿠키 전환"은 쓰지 않았다.** 지금은 Bearer 라 CSRF 가 원천적으로
    불가능한데, 쿠키로 바꾸면 그 문을 새로 열고 `SameSite`·CSRF 토큰을 다시 설계해야 한다.
    출시일에 **새 공격면을 여는 큰 이동**을 하는 대신, 실제 공격만 닫는 작은 결속을 골랐다.
    쿠키는 세션 저장소를 손볼 때 함께 본다.
- **로그아웃이 정작 그 기기를 못 끊을 수 있었다.** `killSessions` 가 `KV.list` 결과만 지웠는데,
  방금 만든 세션은 목록에 없을 수 있다(최종 일관성 ≤60초) — 로그인하자마자 로그아웃한 사람의
  **눈앞의 기기**가 하필 그 경우다. 키를 손에 들고 있으니 목록을 기다릴 이유가 없어 명시 삭제한다.
  - 남는 창은 "다른 기기가 60초 안에 만든 세션"뿐이다. 계정마다 폐기 시각을 두자는 제안은
    **그 읽기도 KV 라 같은 최종 일관성을 진다** — 요청마다 읽기를 하나 늘리고도 창이 안 닫힌다.
- **레이트리밋은 KV 카운터로 만들지 않는다.** 그 쓰기가 바로 8/11 오전에 없앤 것이다(무료 플랜
  하루 1,000 writes). 실효가 있는 건 ① 친구 수 상한 50 ② 외부 OAuth 호출 10초 타임아웃뿐이라
  그 둘만 넣었다. 진짜 레이트리밋은 Cloudflare 대시보드의 규칙 자리다(코드가 아니다).
- **옛 Worker 가 아직 살아 있었다.** `shhh-api.bu202.workers.dev` 가 **같은 KV** 를 보고 있고,
  거기엔 오늘 넣은 방어가 하나도 없다 — 문이 둘이면 잠금은 약한 쪽을 따른다.
  `worker/wrangler.jsonc` 를 지웠다(그 명령이 문을 되살린다). **배포 자체를 지우는 건 사람 몫이다.**
- **`privacy.html` 이 GitHub Pages·workers.dev 를 말하고 있었다.** Pages 이전(직전 커밋)에서
  문서를 같이 안 고쳤다 — 8/8 에 「문서가 하루라도 늦으면 그동안 앱이 거짓말을 한다」고 적어 놓고
  똑같이 저질렀다. 단어장이 "기기 안에만" 저장된다는 목록 항목도 로그인 시에는 거짓이라 갈라 적었다.

### 4단계에서 정한 것
- **결제는 5단계로 미뤘다.** Play Billing 의 `acknowledge` 는 백엔드가 있어야 하고(안 하면 3일 뒤 자동 환불),
  볼트 노트의 「안 할 것: 서버·백엔드」와 정면으로 부딪힌다. 그래서 지금은 **벽과 상태만** 만들고
  결제 호출은 `requestPro()` **한 곳으로 격리**해 뒀다(그 안에 4단계 구현 순서가 주석으로 있음).
  실제 수익을 켜려면 A) Cloudflare Worker($0, 서버 규칙 깸) B) 후원 링크 C) 현행 유지 중에서 사용자와 합의해야 한다.
- 프로 상태는 `localStorage: shh-pro`. 개발 중 벽 너머를 보려면 **콘솔에서**
  `localStorage.setItem('shh-pro','1')`. `?pro=1` 주소는 2026-08-11 에 지웠다 — 주소 하나로 유료를
  켤 수 있는데 화면은 가격을 말하고 있어서, 결제를 붙이는 순간 그대로 구멍이 된다.
- 벽 문구는 `upsell()` 한 곳에서만 만든다 — 사전 화면과 단어장 화면에서 말이 갈리지 않게.
- ⚠️ **2026-08-11: 베타 동안 벽을 껐다** (`BETA_NO_WALL = true`, `PRO_PRICE = ""`).
  벽 자체가 문제가 아니라 **막다른 길**이었다 — 닿으면 `₩4,900` 버튼이 뜨는데 누르면
  "결제는 앱(Play 스토어) 버전에서 열려요"로 끝나서, 사용자가 결제도 못 하고 담지도 못했다.
  **파는 물건이 없는데 값을 부르지 않는다.** `FREE_LIMIT`·`upsell()`·`bookCost()`·마스터 판정은
  손대지 않았으니 결제(5b)가 붙는 날 `BETA_NO_WALL` 한 줄만 `false` 로 되돌리면 그대로 돌아온다.
  - 그때 **서버 판정도 같이 옮긴다.** 지금 `isPro` 는 localStorage 라 콘솔 한 줄로 켤 수 있는데,
    팔기 시작하는 순간 그게 그대로 구멍이 된다(벽의 단위가 손짓 수라 서버가 사전을 알아야 한다).

### 2단계에서 정한 것
- **단어장에 저장하는 건 문자열 하나뿐** (`localStorage: shh-wordbook`). 뜻·그림은 매번 사전에서 다시 찾는다 —
  사용자가 뜻을 정하지 않는다는 수칙이 자료구조에서부터 지켜지도록.
- **합성은 한 항목으로 담는다** (2026-08-07). `보고싶어` 를 담으면 `"보고 싶다"` **한 줄**이 저장되고,
  부품(보다·원하다)은 `bookItem()` 이 화면에서 다시 펼친다. 예전엔 부품 **두 항목**으로 쪼개 담아서
  사용자가 찾은 말이 단어장에서 사라졌다 — **사용자가 친 말이 곧 단어장의 이름**이어야 한다.
  - `bookItem()` 은 **표제어를 먼저** 본다. `헌금` 은 표제어이면서 합성이기도 한데(결합정보가 표제어에
    붙은 컬럼이라 이런 게 대부분), 사전 화면은 표제어 카드를 보여준다. 순서를 뒤집으면 두 화면이 어긋난다.
    `test-compounds.mjs` 가 이 순서를 직접 잰다(뒤집으면 실제로 실패하는 것까지 확인함).
  - 연습도 합성을 **통째로** 낸다 — 부품 손짓을 ①② 나란히 보여주고 뜻을 묻는다. 첫 부품만 보여주면
    '보고싶다'를 묻는데 [보다] 그림만 떠서 문제 자체가 거짓말이 된다.
  - `mergeFromHash` 도 `bookItem` 으로 받는다. `lookup` 만 보면 합성이 표제어가 아니라서
    **링크로 보낸 단어가 조용히 사라진다.**
- **링크 공유는 URL 조각**: `#w=<base64url(단어\n단어…)>`. 5단어 66자, 서버 0. 받으면 병합하고
  `history.replaceState`로 해시를 지운다(새로고침 중복 방지). `scripts/test-book.mjs`가 한글 왕복을 검증.
- **무료 5개**(`FREE_LIMIT`)는 **손짓 수**로 센다. 합성어는 부품 수만큼 차지한다(보고싶어 = 2칸).
  한 항목으로 보이게 바꿨다고 값이 싸지지는 않는다 — 외울 손짓 수는 그대로다.
  ⚠️ 그래서 **문구에 '단어'라고 쓰면 안 된다.** "무료 단어장은 5개까지"라고 해놨더니 합성 3단어를
  담은 사람에게 거짓말이 됐다(단어는 3개인데 이미 막힘). 지금은 양쪽 다 "손짓 N개"로 말한다.
- **연습 문제는 단어장에서만 출제.** 안 배운 걸 묻지 않는다. 3개 미만이면 안내만.
- 화면 전환은 `[data-screen]` ↔ `.tab[data-go]` 한 쌍. 새 화면은 이 두 속성만 붙이면 붙는다.
- **홈이 첫 화면**(home·dict·book·quiz 4개). 홈엔 **오늘의 수어 1개 + 단어장 요약**만 둔다.
  오늘의 수어는 **날짜 해시**로 정한다(무작위 아님) — 같은 날 두 사람이 **같은 단어**를 봐야 하기 때문.
  날짜 문자열은 서로 닮아서 `h*31` 로는 값이 뭉친다(365일에 288개) → **FNV-1a**(353개). `test-home.mjs` 가 지킨다.
  "최근 찾은 단어"는 일부러 안 만들었다 — 저장소가 하나 더 늘고, 없어도 홈이 성립한다.

## 제약 (바뀌지 않는 전제)
- 예산 **$0**. 정적 호스팅(GitHub/Cloudflare Pages).
- **서버는 로그인·단어장 동기화 하나뿐이다** (2026-08-07 에 「안 할 것: 서버」를 여기서만 깼다).
  `worker/index.js` — Cloudflare **Pages Functions + D1**, 무료 한도 안. **앱은 서버 없이도 온전히 돈다** —
  로그인은 얹는 기능이지 단어장이 서 있는 조건이 아니다. 새 기능을 서버로 미루기 전에 이 문장을 다시 읽을 것.
  - ⚠️ **2026-08-11 에 KV → D1 으로 옮겼다.** 8/7 의 "저장하는 게 단어 배열 하나뿐이라 SQL 이 과하다"는
    판단은 **친구 기능이 생기는 순간 틀린 것이 됐다** — 관계는 두 사람에 걸친 데이터고 KV 엔 트랜잭션이
    없다. 자세한 건 아래 「D1 이전」 절과 `docs/D1_MIGRATION.md`.
- Vanilla HTML/CSS/JS, **빌드 도구·프레임워크 없음**. 의존성 최소.
- 결정은 항상 **장단점 + 비용**을 표로 제시하고 승인받은 뒤 진행. 단계마다 실제 브라우저로 검증.

## 시뮬레이터로 확인하기 (실제 앱처럼 도는지)

크롬을 폰 크기로 줄이는 건 확인이 아니다. **Xcode 시뮬레이터가 진짜 WebKit**이고, 출시 대상도 거기다.

```bash
xcrun simctl boot "iPhone 17 Pro"; open -a Simulator   # 부팅 ~20초
xcrun simctl launch booted com.apple.mobilesafari      # 안 띄우면 openurl 이 타임아웃
xcrun simctl openurl booted "http://$(ipconfig getifaddr en0):8000/index.html#q=보고싶어"

python3 scripts/sim.py shot /tmp/x.png   # 그냥 Read 로 보면 된다
python3 scripts/sim.py tap 603 2112      # 좌표는 스크린샷 픽셀(1206x2622) 그대로
```

- **타이핑은 안 된다.** CGEvent 유니코드는 시뮬레이터 HID 로 안 들어간다. 그래서 화면은 **URL 로 만든다**:
  `#q=<단어>` 단어 하나, `#w=<base64url>` 단어장. 링크는 `node -e '…Buffer.from(ws.join("\n")).toString("base64url")'`.
- **Safari 캐시가 옛 JS 를 문다.** `scripts/serve.py`(no-store)로 띄우고, 그래도 옛것이 뜨면 **포트를 바꿔라**(8001).
  URL 이 바뀌면 캐시 키가 달라져 확실히 새로 받는다. 시뮬레이터엔 하드리로드가 없다.
- **해시만 바뀌면 리로드가 안 된다** — 앱을 열어둔 채 공유 링크를 누르면 아무 일도 안 일어났다.
  `hashchange` 로 받도록 고쳤다(`openHash`). 같은 해시를 두 번 열면 이벤트가 안 나니 `?t=$(date +%s)` 를 붙여 확인할 것.
- **결제는 어떤 시뮬레이터로도 확인 못 한다.** Play Billing 은 서명된 빌드를 내부 테스트 트랙에 올려야 열린다(5단계).
  iOS Safari 에선 `getDigitalGoodsService` 가 없어 "결제는 앱(Play 스토어) 버전에서 열려요" 안내가 뜨는 게 정상.

확인 완료(2026-08-05, iOS 26.4 / iPhone 17 Pro): 안내문 → 사전(보고싶어 = 보다+원하다 2카드) → 담기 → 우리 단어장 5개 벽 → ₩4,900 안내 → 연습 출제.

## ⚠️ 함정과 실수 (다음 세션은 반복하지 말 것)

이번 개발에서 실제로 부딪힌 것들. 대부분 시간 잡아먹은 원인.

1. **keyword 검색이 사실상 안 됨.** kcisa getCTE01701은 비어있지 않은 `keyword`에 대해 데이터에 있는 단어("호랑이")조차 **0건** 반환. 부분검색 미지원 → 키워드 큐레이션 방식은 버리고 **전체 수집(numOfRows 크게)** 후 클라이언트에서 처리. `keyword=`는 비어도 URL에 **반드시 포함**해야 함(kcisa 주의사항).

2. **`title`이 동의어 쉼표 묶음.** 예 `"감사합니다,감사,고맙다"`. 그대로 word로 쓰면 "감사"가 매칭 안 됨. → 쉼표 split 후 **첫 단어=word, 나머지=aliases**. (`normalizeEntry`)

3. **이미지가 `http://` (sldict.korean.go.kr).** https 배포 시 **혼합콘텐츠로 차단**. → `httpsify()`로 https 승격. (sldict는 https 지원 확인됨)

4. **설명에 이중 인코딩 HTML 엔티티.** 예 `4&amp;#8231;5지` → `4‧5지`. `decodeEntities()`로 `&amp;` 먼저 푼 뒤 숫자 엔티티 디코드.

5. **인덱스 충돌(같은 별칭이 여러 표제어에).** "감사"가 `감사합니다`·`점검` 양쪽 별칭 → 순진하게 `Map.set`하면 뒤엣것이 이겨 오매칭. → `buildIndex`를 **표제어 우선 + 별칭 충돌은 먼저 온 것 우선** 2패스로.

6. **브라우저 HTTP 디스크 캐시.** JS를 고쳐도 `navigate`/새로고침으론 옛 파일이 뜸(SW 지워도). 개발 중엔 **하드리로드(Cmd+Shift+R)** 필요. 검증 시 `buildIndex.toString().includes(...)`로 새 코드 로드 여부부터 확인.

7. **Service Worker stale 캐시.** cache-first면 dict/JS 수정이 안 보임. → **network-first + 캐시 폴백**으로 통일(현재 방식). 배포 땐 이걸로 충분.

8. **zsh는 따옴표 없는 변수를 단어분리 안 함.** `for r in $list`가 한 덩어리로 돎. → **배열** `arr=(...)` + `"${arr[@]}"` 사용.

9. **Wikimedia는 반복 다운로드에 HTTP 429.** 지화 이미지 32장 루프 다운로드 시 rate-limit. → `--retry`/`--retry-delay`로 간격 두고 재시도. CDN 직링크(`upload.wikimedia.org`)도 IP 스로틀 걸리면 동일.

10. **지화 된소리 근사.** ㄲ=ㄱㄱ 등은 Wikimedia 세트에 전용 이미지가 없어 근사 표기 `[?]`. 현행 표준과 미세차이 가능.

11. **`hidden` 속성 vs `display:flex`.** `.io { display:flex }`가 HTML `hidden` 속성(`[hidden]{display:none}`)을 덮어써서 안 숨겨짐. → 전역 `[hidden]{display:none !important}` 추가로 해결. display 규칙 있는 요소를 hidden으로 토글하면 항상 주의.

12. **MediaPipe는 CDN 동적 import.** `import('https://cdn.jsdelivr.net/npm/@mediapipe/tasks-vision@0.10.14/vision_bundle.mjs')` + WASM fileset + `hand_landmarker.task`(~7MB, googleapis). **오프라인/배포 시 로컬 vendoring 필요**(현재 CDN 의존, SW 미캐시). 카메라는 secure context(https/localhost) 필수. 모드 이탈 시 트랙 stop 필수(프라이버시).

13. **`app.js` 최상위에서 브라우저 전역을 쓰면 테스트가 전부 죽는다.** 4단계에서 `localStorage`/`location`(`?pro=` 처리)을
    최상위에 넣자 `app.js` 를 통째로 평가하는 테스트 4개가 한꺼번에 ReferenceError. 고친 자리만 보고 넘어가서 못 봤다.
    → 스텁을 `scripts/_app.mjs` 한 곳에 모았다. 새 전역을 쓰면 **여기 스텁도 같이 늘린다**.

14. **표제어 문자열은 수형을 못 정한다 — 동음이의.** `보다`는 사전에 표제어가 둘이다:
    `IMG000227009`=[시각], `IMG000227011`=조사 '~보다'(텍스트 사전의 `에서④`와 수형 설명이 같다).
    앱이 늘 첫 후보를 집어서 **'보고싶다'에 조사 수형이 떴다** — ⛔ 규칙 위반이 실제로 일어난 사례.
    → 검증 대장의 부품은 **`보다@IMG000227009`** 처럼 그림 파일 이름으로 수형을 못박는다.
      해석은 `lookup()` 한 곳(`js/app.js`), 표시는 `bare()`로 `@` 뒤를 뗀다. 단어장·연습도 같은 경로.
      **단어장에 담을 때도** `pinned()` 가 화면에 뜬 그 수형을 못박아 저장한다 — 안 그러면
      사전에서 본 수어와 단어장·연습의 수어가 달라진다(같은 구멍이 두 군데였다).
      `verify.mjs --add` 는 수형이 여럿이면 후보를 보여주고 **멈춘다**(사람이 고른다).
      `verify.mjs --check` 는 못박히지 않은 부품·사라진 그림을 잡는다. `test-compounds.mjs` 가 회귀검증.

15. **활용형은 어미만 떼서는 안 풀린다 — 어간이 변한다.** `ENDINGS`(어미 제거)만으로는
    고마워→고맙다, 기다려→기다리다, 배고파→배고프다, 괜찮아→괜찮다를 못 찾는다.
    못 찾으면 그리디가 **1글자로 떨어져** 조각 오답을 낸다: **배고파 = 배(선박)+고+파(대파)**.
    → `deconjugate()` 로 어간 역변환 후보를 하나 만들어 조회한다(ㅂ불규칙·려→리다·아/어 제거·ㅡ탈락).
      과생성(만나→만느다)은 **사전에 없어서 그냥 버려지므로 무해** — 조회가 곧 검증이다.

16. **문장 안에서 1글자 표제어를 잡으면 거의 언제나 오답.** 1글자 키가 인덱스에 **394개** 있고
    그중 `는·은·를·을·이·의·도·만·과·와·고` 가 **표제어로** 들어있다(텍스트 사전에 조사 표제어가 있다).
    실제로 **잘자=잘하다+사람(者)**, **힘내=기운+자신** 이 떴다.
    → `matchSentence` 에서 `L===1 && s.length>1` 이면 매칭하지 않는다. 지화로 떨어지는 게 정직하다.
      "표제어일 때만 허용"으로 완화하면 조사가 손짓으로 나오므로 **불가**(측정해서 버린 안).
      대가: "나 배고파"의 `나`를 놓친다. 조사를 수어로 내놓는 것보다 낫다고 판단.

17. **별칭으로 매칭된 카드에 표제어만 쓰면 사용자가 친 말과 화면이 어긋난다.**
    `축하해` → 카드에 `식`(式)만 떴다. 사전 근거는 있지만(축하=식의 별칭) 사용자는 자기가 안 친 말을 본다.
    → `entryCard(e, key)` 로 `축하 (식)` 표기. 합성 카드의 `라벨 (표제어)` 형식과 같다.
    ⚠️ `alts.map(entryCard)` 처럼 넘기면 **map 의 index 가 key 로 새서** `1 (해내다)` 가 된다. 화살표로 감쌀 것.

18. **자동 추출 합성은 최상위 카드로 안 뜬다 — 전부 "어떻게 만들어졌나" 펼침 안에 있다.**

    ```bash
    gh api repos/bu202/shhh-app/pages/builds --jq '.[0:3][] | "\(.status) \(.commit[0:7]) \(.duration)ms \(.error.message // "")"'
    ```

    ⚠️ **한 번 성공했다고 원인을 단정하지 말 것.** `.nojekyll` 을 뺀 뒤 성공했지만 그 사이 12시간이
    지나 있었다 — 되돌려 다시 배포해서야 무죄가 확인됐다. 배포 실패는 재현 창이 시간에 묶여 있어

      개인정보처리방침 링크도 안 넣는다 — 푸터가 모든 화면에 이미 달고 있어 한 화면에 두 번 나온다.
    - 로그인 버튼은 `loginButtons()` **한 함수**가 만든다. 헤더 패널과 게이트가 따로 만들면

    - 링크(`#w=`)로 들어온 사람이 로그인하러 떠나면 해시가 날아간다 → `shh-back` 에 맡겼다가
      돌아와서 되돌린다. 게이트가 막을 땐 `replaceState` 도 **안 한다**(안 그러면 링크가 조용히 사라진다).

42. **`<svg>` 에는 `el.hidden = true` 가 안 먹는다.** `hidden` 은 **HTMLElement** 의 IDL 속성이라
    SVGElement 에선 JS 프로퍼티만 생기고 HTML 속성으로 반영되지 않는다 — `el.hidden` 은 `true` 인데
    `getAttribute("hidden")` 은 `null` 이고 화면은 그대로다(설정 화면에서 헤더 마스코트가 안 숨겨졌다).
    → `el.toggleAttribute("hidden", 조건)`. `toggleAttribute` 는 **Element** 의 것이라 태그를 안 가린다.
    ⚠️ HTML 에 `<svg hidden>` 이라 직접 쓴 건 파서가 속성으로 넣어 잘 동작한다 — **JS 로 켜고 끌 때만**
      깨진다. 그래서 마스코트 심볼 정의(`<svg hidden>`)는 여태 멀쩡했다.

41. **네이버만 「서비스 URL 도메인 = Callback URL 도메인」을 요구한다.** 카카오·구글은 콜백 도메인을
    안 따져서 `shhh-api…workers.dev/cb/…` 그대로 통과했는데, 네이버는 서비스 URL 에 없는 도메인으로
    콜백이 오면 **"개발자센터에 등록되지 않은 사이트"** 로 거부한다. 우리는 앱(Pages)과 콜백(Worker)이
    다른 도메인이라 이 조건에 정면으로 걸린다.
    → 네이버 콘솔의 **서비스 URL 에 Worker 도메인도 추가**한다(다중 등록 지원). 앱 주소는 남겨 둔다 —
      검수 때 사람이 그 주소로 서비스를 확인한다.
    ⚠️ **제공자 세 곳이 같은 규칙일 거라고 가정하지 말 것.** 카카오·구글이 되니까 네이버도 될 줄 알고
      같은 값을 적어줬다가 틀렸다. OAuth 는 표준이지만 **등록 심사 규칙은 회사마다 다르다.**

40. **별명은 제공자에게 받지 않고 사용자가 짓는다.** 이름·이메일을 카카오에서 받으면 비즈앱 전환

    - 별명을 고치면 `touch()` 로 **시각도 같이 올린다.** 안 올리면 다음 동기화에서 서버가 더 새것으로
      판정돼 방금 지은 별명이 되돌아간다.
    - 입력 글자는 **16px**(함정 31). 새 `<input>` 을 만들 때마다 걸리는 자리다.

39. **iOS 시뮬레이터의 Safari 네이티브 메뉴는 합성 탭을 안 받는다.** 「홈 화면에 추가」를 하려고
    ⋯ → 공유를 탭했는데 메뉴가 그대로였다(두 번 시도, 좌표는 맞았다). 웹 페이지 안의 요소는
    `sim.py tap` 으로 잘 눌리지만 **UIKit 메뉴는 다르다.**
    → PWA 설치 후 동작은 **실기기에서** 확인한다. 시뮬레이터로는 설치 전 화면까지만 검증된다.
    ⚠️ 그래서 **설치된 PWA(standalone)에서 로그인 리다이렉트가 앱으로 돌아오는지는 아직 미확인이다.**
      브라우저 탭에서는 라이브 주소로 끝까지 확인됐다.

37. **동기화는 사전이 선 뒤에 시작해야 한다.** `replaceBook` 이 `bookItem()` 으로 단어를 거르는데,
    사전 로드 전에 서버 단어장을 받으면 **전부 "사전에 없음"으로 버려진다** — 다른 기기의 단어장이
    통째로 사라지는 사고다. 그래서 `appReady?.()` 를 `main()` 의 사전 로드 **뒤**에 뒀다.

60. **배포 검증 명령이 세 가지로 거짓말한다 — 셋 다 "안 고쳐졌다"로 읽힌다.** 레포 전체 공개를
    막고 확인하는데 `/CLAUDE.md` 가 계속 **200** 이었다.
    - ① **Pages 는 없는 경로에 `index.html` 을 200 으로 준다**(SPA 폴백). 상태코드로 보면 파일이
      아직 있는 것처럼 보인다 → **`Content-Type` 이나 본문**을 봐야 한다(`text/html` 이면 사라진 것).
    - ② **엣지 캐시가 옛 파일을 붙들고 있다**(`cf-cache-status: HIT`, `s-maxage=604800` = 7일).
      배포는 깨끗한데 맨 URL 만 옛것이다 → **`?cb=$RANDOM`** 을 붙여야 실제 배포본을 본다.
      ⚠️ `*.pages.dev` 는 Cloudflare 소유 존이라 **퍼지할 수 없다.** 커스텀 도메인이 붙으면 풀린다.
    - ③ **Pages 가 `/privacy.html` 을 `/privacy` 로 308 보낸다.** `-L` 이 없으면 빈 본문을 받고
      "방침이 배포 안 됐다"고 오진한다(실제로 그랬다).
    → `curl -sL … "?cb=$RANDOM$RANDOM"` 로 재고 **Content-Type** 을 본다. 함정 30·48 의 연장선이다:
      **결과가 이상하면 코드보다 측정 방법을 먼저 의심한다.**

61. **가짜 저장소는 "무엇이 실패할 수 있는가"를 지운다.** `test-friends` 의 가짜 KV 는 `Map` 이라
    절대 실패하지 않고 즉시 일관적이었다 — 그런데 D1 이전에서 재려던 것이 정확히 **제약·트랜잭션·
    `changes` 카운트**였다. 흉내내면 아무것도 안 재게 된다(함정 50 의 재발이다).
    → `scripts/_d1.mjs` 가 `node:sqlite` 로 D1 규약을 얹는다. UNIQUE 충돌도 외래키 CASCADE 도
      `BEGIN/ROLLBACK` 도 **실제로** 일어난다. **가짜로 대체하려는 것이 재려는 것이면 가짜를 쓰면 안 된다.**
    - 곁가지: 이때 쓴 검사 하나가 **항진명제**였다(양변이 같은 식이라 늘 통과). 표본 2개 대신
      **실데이터 400건**에 대고 "출제된 것에는 미확정 부품이 없다"로 바꿔야 실제로 물린다.

62. **`wrangler d1 create` 가 만드는 바인딩 이름은 `shhh_db` 다** — 코드가 쓰는 `DB` 가 아니다.
    출력에 나온 스니펫을 그대로 붙여넣으면 `env.DB` 가 undefined 라 **모든 요청이 500** 이 된다.
    → `wrangler.jsonc` 에 `"binding": "DB"` 로 적는다. `pages dev` 시작 로그의 바인딩 표에서
      `env.DB (shhh-db)` 가 뜨는지 확인하는 게 가장 빠르다.

56. **`wrangler kv` 는 `--remote` 없이는 로컬 시뮬레이션을 본다.** wrangler 4 에서 `kv key list` 가
    `worker/.wrangler/` 안의 miniflare 저장소를 읽는다. 실제 KV 에 세션 11개·단어장 4개가 있는데
    화면엔 **"0개"** 가 떴고, 그대로 믿었으면 "지울 세션이 없다"고 넘어갈 뻔했다.
    → KV 를 볼 때는 늘 `--remote`. **"없다"는 답을 받으면 조회 방법부터 의심한다** — 함정 46
      ("응답이 없다"와 "없다는 응답"은 다르다)의 도구판이다.
    ⚠️ **`wrangler d1 execute` 도 똑같다.** 저장소가 KV 에서 D1 로 바뀌었다고 이 함정이 사라지지
      않는다 — `--remote` 없이 돌리면 `.wrangler/` 안의 로컬 DB 를 보여주고 그건 늘 비어 있다.
    곁가지: `.wrangler/` 는 이 조회가 만든다. `.gitignore` 에 넣었다.

58. **`_headers` 의 CSP 는 Service Worker 에도 붙는다 — 그리고 SW 안의 위반은 조용하다.**
    Cloudflare Pages 로 옮기며 `connect-src 'self'` 로 조였더니 **수형 그림이 한 장도 안 떴다.**
    `img-src` 는 sldict 를 허용하고 있었는데도 그렇다 — 막힌 것은 이미지 태그가 아니라 **SW 의
    `fetch`** 다(런타임 캐시 때문에 SW 가 모든 GET 을 대신 받는다). 정책이 `service-worker.js`
    응답에도 붙어 SW 컨텍스트를 지배한다.
    ⚠️ **SW 안의 위반은 문서의 `securitypolicyviolation` 에 안 잡힌다.** 콘솔도 조용하고 화면엔
      그림만 없다. 예외를 빼고 배포해 **대조하기 전까지 원인을 못 찾았다.**
    - meta CSP 시절엔 정책이 **문서에만** 붙어 SW 가 자유로웠다. 그래서 여태 안 보였다.
    - 그래서 `connect-src` 에 sldict 예외가 있다. SW 가 외부 요청을 그만두면 지울 수 있지만
      본 적 있는 그림의 오프라인 캐시를 잃는다(실측: SW 가 그림 3장을 캐시한다).

59. **`Referrer-Policy: no-referrer` 를 넣자 sldict 가 503 을 줬다.** 58 을 고친 뒤에도 그림이
    안 떠서 두 번째 원인을 따로 찾아야 했다. **같은 이미지를 `curl` 로 받으면 referer 없이도 200** 이라
    서버 응답만 봐서는 안 보인다 — 옛 주소(GitHub Pages)와 새 주소를 **나란히 열어** 한쪽만 뜨는
    것으로 갈랐다. 지금 값은 `strict-origin-when-cross-origin`(브라우저 기본값, origin 까지만).
    ⚠️ 보안 헤더는 **조일수록 좋은 게 아니다.** 외부 자원에 기대는 앱에서는 한 칸 조일 때마다
      실제로 열어 보고 넘어갈 것. 이 둘은 테스트가 못 잡는다(함정 32 와 같은 부류).

57. **`allowed()` 하나가 CORS 와 로그인 복귀 주소를 둘 다 정한다.** 폰 없이 확인하려고 열어 둔
    `localhost|127.0.0.1|192.168.*` 이 **세션 토큰의 출구**였다 —
    `/login/kakao?return=http://192.168.1.9:8000` 이면 제공자 로그인을 마친 토큰이 그 주소의
    `#login=` 으로 간다. 같은 와이파이(카페·기숙사)에 있는 사람이 링크 하나로 남의 계정을 가져간다.
    → 개발용 갈래는 `env.DEV_ORIGINS === "1"` 뒤에 둔다. **`wrangler.jsonc` 에 안 적는다** —
      비어 있으면 앱 주소 하나만 허용한다(마스터 계정과 같은 규칙: 기본값이 안전한 쪽).
      `test-friends.mjs` 16~20 이 복귀 주소와 CORS 를 같이 잰다.
    대가: **로컬·LAN 에서 로그인이 안 된다.** 사전·수형·연습은 그대로다. 로컬에서 로그인을 봐야 하면
      운영 Worker 를 여는 게 아니라 **개발용 Worker 를 따로** 세운다.
    ⚠️ 배포 뒤 **세 번은 재라.** 1차엔 옛 코드, 2차엔 LAN 만 닫히고 localhost 는 열린 채로 보였다.
      한 번만 쟀으면 "고쳤는데 안 먹힌다"고 오진했을 자리다(함정 48 이 그대로 재현됐다).

## ⛔ 절대 규칙 — 실제 수어만 보여준다

앱의 목적이 **수어를 알리는 것**이라 틀린 수어를 보여주면 목적을 정면으로 배신한다.

1. **뜻을 지어내지 않는다.** 사용자가 단어에 임의의 뜻을 붙이는 기능은 만들지 않는다.
2. **그림은 반드시 그 표제어의 것.** 아무 지화 사진이나 자리채움으로 쓰지 않는다(v1 목업에서 실제로 저지른 실수).
3. **사전에 없다 ≠ 개념이 없다.** `보고싶다`는 표제어가 없지만 실제로는 **[보다]+[원하다]** 합성이다.
   사전만 보고 "그리워하다와 같은 말"로 넘겨짚었다가 틀렸다. **그립다는 별개 단어다.**
4. **손가락 번호는 상식과 반대**: `1지=검지 2지=중지 3지=약지 4지=새끼 5지=엄지`.
   설명의 84%가 이 표기를 쓴다 → `namedFingers()`가 렌더 직전 이름으로 치환(+조사 보정). `scripts/test-fingers.mjs`가 회귀검증.

### 새 단어를 넣기 전 절차
```bash
npm install                             # 최초 1회 — scripts/ 전용 devDependency(@anthropic-ai/sdk)
node scripts/screen.mjs <단어>          # 유튜브 검색 → Haiku가 "볼 만한 영상" 순위만 매김(판정 아님)
node scripts/screen.mjs <단어> --raw    # 키 없이 검색 결과만
node scripts/verify.mjs <단어>          # 앱이 지금 뭐라 답하는지 + 확인할 유튜브 검색 링크
# → 영상을 실제로 보고 확인한 뒤에만
node scripts/verify.mjs --add "<단어>" "<부품1+부품2>" "<영상URL>" "<근거메모>" "<채널명>"
#   부품에 수형이 여럿이면 멈추고 후보를 보여준다 → "보다@IMG000227009" 처럼 못박아 다시 실행 (함정 14)
node scripts/verify.mjs --check         # 대장이 사전과 아직 맞는지
node scripts/test-compounds.mjs         # 문장에서 실제로 잡히는지
```
- 출처는 **국립국어원이 아니어도 된다.** 통용되는지가 기준. 다만 대장에 URL과 근거(몇 초 자막 등)를 남긴다.
- **Claude API를 검증자로 세우지 않는다.** 손 그림 판독은 이 프로젝트에서 두 번 틀렸다(지화 ㅗ 오판,
  "보고싶다=그리워하다" 오판). API는 *후보를 좁히는 데만* 쓴다 — 유튜브 검색 결과 중 그 단어를 실제로
  가르치는 영상 고르기, 사전 설명 두 개가 같은 동작인지 텍스트 비교, 확인 우선순위 매기기. 전부 텍스트
  작업이고 틀려도 사람이 거른다. **최종 판정(`--add`)은 항상 사람.**
  비용 참고(2026-08): 텍스트 대조는 Haiku 4.5로 단어당 ₩2.5, 전체 12,943단어 ₩33,000(Batch API 50% 할인 시 ₩16,000).
  비전 대조는 Opus 5로 단어당 ₩77 — 전수(₩103만)는 낭비고 의심 케이스 100개(₩7,700)면 충분. 병목은 비용이 아니라 사람이 영상 보는 시간.
- **유튜브 재생목록/영상은 WebFetch로 못 읽는다**(JS 렌더). Chrome으로 열고 `javascript_tool`로
  `video.currentTime`을 옮겨가며 `zoom` 캡처하면 자막과 손모양을 읽을 수 있다.
- ⚠️ 영상 내용을 프레임으로만 확인하는 것은 한계가 있다. 확신 없으면 대장에 넣지 말고 미검증으로 둔다.

복사한 SKILL.md 본문 맨 아래에 아래를 그대로 붙인다. 이게 STEP 6 의 전부다.

```markdown

제품: shhh! — 연인·친구가 실제 한국수어를 배워 소리 없이 대화하는 PWA.

목적은 판매가 아니라 **수어를 알리는 것**이다. 카피가 그 목적을 깎으면 카피가 진다.

절대 쓰지 않는다:
- 수어 실력·습득 속도에 대한 약속 ("N일 만에", "마스터", "유창하게")
- 정확성 단정. 일상어 219개 중 영상으로 확인된 건 8건(3.7%)이다.
  "정확한 수어" / "검증된" 은 사실이 아니다. 앱 스스로 "(확인 안 됨)"이라 말한다.
- 농인·수어를 도구나 장식으로 쓰는 표현. 비장애인 커플의 "비밀 놀이"로만 그리지 않는다.
- 긴급성·희소성 압박 (한정, 마감, 지금 안 하면)
- 이메일 수집·리드 마그넷·팝업·전환 추적을 전제한 제안.
  「안 할 것: 서버」 규칙이 있다. 예외는 로그인/동기화용 Cloudflare Worker 하나뿐이다.

지킨다:
```

### 스킬은 원본에서 고치지 않는다 — 복사본을 만든다
플러그인은 업데이트할 때 **자기 폴더를 통째로 새로 쓴다.** 캐시(`~/.claude/plugins/cache/…`) 안에서
고친 내용은 경고 없이 사라진다. 복사할 자리는 `~/.claude/skills/<폴더이름>/SKILL.md` 이고,
**명령어가 되는 건 파일 안 `name` 이 아니라 폴더 이름**이다. 맨 위 `---` 두 줄 사이는 건드리지 않는다.

```bash
S=~/.claude/plugins/cache/marketingskills/marketing-skills/2.10.0/skills
for k in copywriting cro pricing; do
  mkdir -p ~/.claude/skills/$k && cp -R "$S/$k/." ~/.claude/skills/$k/
done
```
마케팅 팩이 꺼져 있어 **이름이 안 겹친다** — 폴더 이름을 원본 그대로 두면 `/copywriting` 으로 불린다.

- 🔶 KNN 실손 튜닝 (진행 중)
  - 32자모 × 8 = **256 샘플 수집 완료** (localStorage 키 `ksl-knn-samples`, 브라우저 전용·레포에 없음). 브라우저 데이터 지우면 소실 → 필요시 백업: 콘솔에서 `localStorage.getItem('ksl-knn-samples')`.
  - 백업 검증 완료: 32자모 = 자음 15(ㄱㄴㄷㄹㅁㅂㅅㅇㅈㅊㅋㅌㅍㅎ+ㅆ) + 모음 17. 빠진 ㄲㄸㅃㅉ/ㅘㅙㅝㅞ는 **조합으로 만드는 자모라 학습 불필요**.
  - 계기판 커밋됨(`1ae8b05`): 카메라 상태줄에 `최근접 <자모> d=<거리> (임계 N)`.
  - **`KNN_MAX=15`** (`1fdfe45`). 백업 256샘플을 앱과 같은 거리식(제곱합)으로 실측한 값 기준 — 이전 40은 근거 없는 추정(“다른자모 d~183”은 극단쌍 하나)이라 사실상 거부가 없었음:
    | 지표 | 값 |
    |---|---|
    | 같은자모 최근접 | 중앙 0.01 / **최대 5.32** |
    | 다른자모 최근접 | 중앙 1.42 / **최소 0.42** (ㅠ↔ㅆ) |
    | 붙은 쌍 top5 | ㅠ↔ㅆ 0.42, ㅕ↔ㄷ 0.55, ㅠ↔ㅅ 0.73, ㅗ↔ㅚ 0.87, ㅁ↔ㅍ 0.90 |
  - **임계는 자모를 가려내지 못한다**(클래스가 0.42까지 붙음). 역할은 *지문자 아닌 손 거부*뿐. 자모 구분은 k-이웃 투표 몫.
  - ⚠️ **LOO 99.2%는 과대평가**: 자모당 8장이 1.8초 정지버스트 → near-duplicate. `node scripts/test-knn.mjs`가 이 수치+클래스간 거리+비자모 거부를 회귀검증(앱의 실제 `features`/`knnClassify` 사용).
  - **남은 것**:
    1. 실사용하며 상태줄 `d=` 관찰 → 미인식 잦으면 15↑, 아무 손이나 잡히면 15↓.
    2. 혼동 잦은 자모만 **자세 바꿔가며**(위치·거리·각도) 추가 수집 → 정지버스트 누수 해소.
    3. 하이브리드 폴백(미뤄둠): `const label = (knn == null) ? recognizeSign(lastLm) : knn;`
    4. landmark가 거의 같은 쌍(ㅠ/ㅆ, ㄷ/ㅌ)은 정적 손뼈대의 원천적 한계 → 못 고치면 한계로 기록.
