## 왜 옮기나 (한 문장씩)

| 지금 KV | 증상 | D1 이면 |
|---|---|---|
| 친구 관계를 **두 사람 레코드에 각각** 적는다 | 첫 쓰기만 성공하면 반쪽이 남는다 | 관계 = **행 하나**. 반쪽이 생길 수 없다 |
| 로그아웃이 `KV.list` 에 기댄다 | 다른 기기가 60초 안에 만든 세션은 못 지운다(최종 일관성) | `users.session_version` 을 +1 → **그 순간 전부 죽는다** |
| 계정 삭제가 6번의 개별 삭제 | 중간에 죽으면 반쯤 지워진 계정 | `ON DELETE CASCADE` + 한 트랜잭션 |
| 쓰고 바로 읽으면 옛 값 | "수락했는데 목록이 그대로"(함정 49) | 읽은 직후가 곧 최신 |

**막아 둔 것과 원인은 다르다.** P0-1(양쪽 확인)으로 *권한이 새는 방향*은 이미 닫혔다.
D1 은 그 증상이 아니라 **원인**(관계를 두 곳에 적는 것)을 없앤다.

## 지금이 가장 싼 시점

이전 시점 KV 실측: **계정 1개(개발자 본인) · 친구 레코드 0개 · 전체 5키.**
사용자가 늘면 무중단 이전 설계(이중 쓰기·백필·컷오버)가 필요해진다. 지금은 그게 필요 없다.

## 절차

### 0. 준비 (승인 불필요 — 로컬에서만)
```bash
# 로컬 D1 로 스키마와 코드를 먼저 검증한다. 원격 리소스를 만들지 않는다.
npx wrangler d1 execute shhh-db --local --file=worker/schema.sql
npm test        # D1 경로 테스트가 로컬 D1(miniflare) 위에서 돈다
```

### 1. 리소스 생성 — **승인 필요**
```bash
npx wrangler d1 create shhh-db          # → database_id 를 받는다
```
그 다음 `wrangler.jsonc` 에 추가:
```jsonc
"d1_databases": [{ "binding": "DB", "database_name": "shhh-db", "database_id": "<위에서 받은 값>" }]
```
> `database_id` 는 비밀값이 아니다(KV 네임스페이스 ID 와 같은 성격) — `wrangler.jsonc` 에 적어도 된다.

### 2. 스키마 적용 — **승인 필요**
```bash
npx wrangler d1 execute shhh-db --remote --file=worker/schema.sql
```
재실행 가능하다(`IF NOT EXISTS`). 중간에 죽으면 그냥 다시 돌린다.

### 3. 데이터 이전 — **승인 필요**
계정 1개라 스크립트를 쓰지 않는다. **아무것도 옮기지 않는 것이 가장 안전하다:**
- 개발자 본인 계정 1개 → **다시 로그인하면 새로 만들어진다.**
- 단어장 5단어는 이전 전에 화면에서 확인하고, 필요하면 **링크 공유(`#w=`)로 옮긴다** —
  이미 있는 기능이라 새로 만들 코드가 0이다.
- 친구 레코드 0개, 초대 코드 1개(다시 만들어진다).

> 사용자가 늘어난 뒤에 이 문서를 읽고 있다면 이 절은 **더 이상 유효하지 않다.**
> 그때는 KV 를 읽어 D1 에 넣는 백필 스크립트와 이중 쓰기 기간이 필요하다.

### 4. 코드 전환 — 로컬 작업(승인됨), 배포는 승인 필요
`worker/index.js` 의 저장소 접근을 D1 로 바꾼다. **같은 커밋에서 P1-2(쿠키 세션)도 같이 한다** —
`session_version` 이 D1 에 들어가야 "모든 기기 로그아웃"이 실제로 즉시 듣기 때문이다.
둘을 나눠서 하면 쿠키 전환만 먼저 나가 **CSRF 공격면을 새로 열고 얻는 건 없다.**

바뀌는 자리:
- `internalUid()` → `users` upsert
- `killSessions()` → `UPDATE users SET session_version = session_version + 1`
- 세션 검증 → `sessions.token_hash` 조회 + `session_version` 대조
- 토큰 → **완전 무작위**(uid 를 담을 이유가 사라진다 — `user_id` 는 세션 행에 있다)
- `getFr`/`putFr`/`drop` → `friendships` 한 행에 대한 SQL
- 수락 → `UPDATE ... SET status='accepted'` **한 문장** (`batch()` 로 감싼다)
- 계정 삭제 → `DELETE FROM users WHERE id=?` (CASCADE 가 나머지를 지운다)

### 5. 롤백
| 언제 | 무엇 |
|---|---|
| 배포 직후 이상 | Cloudflare 대시보드 → Pages → shhh-app → 직전 배포 → **Rollback** |
| KV 는 그대로 둔다 | 이전 중에도 **KV 를 지우지 않는다.** 롤백하면 옛 코드가 KV 를 그대로 읽어 돈다 |
| KV 정리 | D1 로 1주일 이상 문제없이 돌고 나서. 지우는 명령은 체크리스트에 |

> ⚠️ **KV 바인딩을 같은 커밋에서 떼지 않는다.** 떼면 롤백해도 옛 코드가 설 자리가 없다.

## 검증 (전환 커밋에 반드시 포함)

기존 `scripts/test-friends.mjs` 76개가 **그대로 통과해야 한다.** 라우트 계약이 안 바뀌기 때문이다 —
가짜 KV 대신 로컬 D1 을 물리고 같은 검사를 돌린다. 그게 이 이전이 옳은지 재는 가장 강한 신호다.

새로 추가할 것:
1. 친구 수락 중간에 SQL 이 죽어도 **반쪽 상태가 남지 않는다**(트랜잭션 롤백)
2. `session_version` 을 올리면 **모든 세션이 그 즉시** 401 (KV 의 60초 창이 사라졌는지)
3. `sessions` 에 **원본 토큰이 없다**(해시만)
4. `invite_codes` 에 **코드 원문이 없다**
5. 계정 삭제가 한 문장이고 CASCADE 로 전부 사라진다
6. 응답에 `provider_subject` 가 절대 안 실린다 (지금 59번 검사를 그대로)

## 안 하기로 한 것

- **`entitlements` 테이블** — 파는 물건이 없다. 결제를 붙이는 날 그때 요구에 맞춰 만든다.
- **단어를 행으로 쪼개기** — 통째로 읽고 통째로 쓰는 게 전부라 조인할 일이 없다. JSON 한 칸이 맞다.
- **스키마 버전 필드** — 필드 몇 개짜리 테이블이다. 필요해지면 그때 `PRAGMA user_version`.
