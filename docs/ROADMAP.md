# ROADMAP.md — 출시 단계표 (2026-09-02 확정)

이 문서는 **제품 출시 여정**(PWA-1~4 · APP-0~6)의 원본이다.
`CLAUDE.md` §1-1 의 `stage-contract` 와 **축이 다르다** — 그 계약은 「보안 1~4단계가 저장소
안에서 닫혔나」를 말하고, 이 문서는 「출시까지 무엇이 남았나」를 말한다.
⛔ **둘을 하나로 합치지 않는다.** `stage-contract` 는 그대로 두고 여기서 참조만 한다.

⚠️ **이 문서는 기계 검사를 받지 않는다.** `scripts/test-docs.mjs` 는 여기의 단계 상태를 재지
않는다. 낡으면 사람이 고쳐야 한다 — 그것이 별도 문서를 고른 대가다(2026-09-02 사용자 결정 4).

## 0. 이 표가 왜 다시 만들어졌나

2026-09-02 이전의 단계표는 **Codex 기억에만** 있었다. 저장소에는 `PWA-1` 이라는 문자열이
돌연변이 역사 두 줄에만 나왔고, 새 세션은 인계서 없이 단계를 알 수 없었다. 실제로 그 상태에서
한 회차가 낡은 목록으로 작업을 시작할 뻔했다.

같은 날 교차검증에서 **오기입 3 · 순서 모순 3 · 누락 4 · 확대해석 2** 가 나왔고, 이 문서는
그것을 반영한 판이다. 무엇이 어떻게 틀렸었는지는 §6 에 남긴다 — 지우면 같은 실수가 돌아온다.

### PWA-2 — 정책·개인정보·계정 결정을 새 회원 설계에 맞춘다
**상태: 🟩 결정은 전부 닫혔다(2026-09-05 · 4차 개정) · 방침 반영과 구현은 남았다**

✅ **PWA-2 안에 열린 물음은 0개다** — 6번(관리자 열람 감사기록)이 **㉨ 2년 고정 · ㉩ 방침의
「안전성 확보조치」 절에 적는다**로 닫혔고(§29-1c), 3번(본인확인기관 위탁)은 **APP-5 로 이연**됐다.
⛔ **「단계가 끝났다」가 아니다** — 남은 것은 **결정이 아니라 반영**이다: 방침 문장(§29-7 초안 ·
production 수집 직전에 찍는다) · 코드(PWA-3·PWA-4).

⏭ **2026-09-05 사용자 결정 — 본인확인기관 위탁(§29-3 의 3번)은 APP-5 에서 한다.**
사업자 등록·유료 계약과 같은 회차로 묶는다(결정 2 와 같은 이유). ⛔ **「닫혔다」가 아니라
「이연」이다** — ⛔ **남는 물음이 있고 그것을 지우지 않는다**: **DI 가 기관을 바꾸면 달라지는가**
(공개 자료가 엇갈린다 · §29-3 3번). 후자가 맞으면 기관 교체 순간 저장된 DI 가 전부 무의미해지고
중복가입 차단(㉠)이 무너진다.

⛔ **그렇다고 지금 서면 질의를 보내지 않는다**(2026-09-05 정정). §29-3 3번이 그 물음을
**「기관 선택의 기준이지 구현 세부가 아니다」**라고 이미 규정했고, **기관 선택은 APP-5** 다.
✅ **PWA-3 설계는 규격을 기다리지 않아도 된다** — ⛔ **「규격이 확정됐다」가 아니다**
(2026-09-05 재확인: NICE 페이지는 **「회원사의 선택에 따라」** 제공한다고 적는다 · §29-3 3번).
**정상 경로는 「실명·전화번호·CI 를 요청하지 않는 것」**이다(APP-5 계약 조건 · 출처가 둘이다 —
실명·전화번호는 **사용자 결정 ㉡′** · CI 는 **2026-09-03 파생 결론** · §29-1a).
DTO 분리는 **요청하지 않은 값이 그래도 왔을 때의 방어 경로**라 규격과 무관하게 필요하다.
⛔ **「전부 온다」를 정상 경로로 적지 않는다.**
⛔ **당시 사실 — 2026-09-05 첫 판:** 이 자리는 *「PWA-3 설계를 막던 부분은 이미 닫혀 있다 —
2026-09-03 규격 조사(NICE 반환 항목 · 선택 수신 없음)로 DTO 분리와 「받아서 즉시 버린다」가
정해졌다」*였다. **그 규격 조사 자체가 틀렸다**(위 재확인).
✅ **대신 답을 몰라도 「조용히 틀리지는 않게」 설계한다** — DI 의 HMAC 버전에 **기관 식별자**를
함께 넣고(§29-4), **옛 기관 행이 남아 있으면 가입 경로를 fail-closed** 시킨다.
⛔ **이것이 중복가입 차단을 지켜 주지는 않는다**(2026-09-05 Codex 독립 검토 1). HMAC 은 키와
입력값의 함수라 **버전에 무엇을 적든 서로 다른 DI 두 개를 이어 주지 않는다.** 인증업체 기준이
맞고 기관을 바꾸면 **차단은 그대로 끊긴다** — 바뀌는 것은 **그 사실이 드러나느냐 조용하냐**뿐이다.
⛔ **그래서 「컬럼 하나로 해결된다」가 아니다** — 기관 식별자는 **감지의 전제**이고, 실제 방어는
**불일치 시 fail-closed 게이트 + 이전·재인증 절차**이며 **그 설계는 PWA-3 의 몫**이다.
⚠️ **`deletion_keys` 가 그 완성형이다**(위협 46) — 라벨만 적은 게 아니라 **키의 검사값을 적고
어긋나면 던지며 자동 판정을 거부한다**(`worker/ledger.js` `rememberDeletionKey`·
`deletionEvidenceUsable`). **거기까지 가야 같은 무늬다.**
⛔ **당시 사실 — 2026-09-05 첫 판:** 이 자리는 *「질의는 무료이고 지금 할 수 있으므로 PWA-3 설계
전에 보낸다」*였다. **저장소의 「3번이 먼저다」를 살리려고 앞당긴 것이고 필요에서 나온 것이
아니었다** — 사용자가 그 근거를 물어 바로잡았다.

✅ **수집 항목이 확정됐다**(2026-09-03 · **2차 개정 반영**) — 중복가입을 막는 이유는
**관계의 신뢰**, **본인확인은 필수**, 저장할 값은 **DI 의 HMAC + 생년월일 원문** 둘,
결정 E 는 **유지**. ⛔ **실명·전화번호는 받지도 저장하지도 않는다.**
원본은 `docs/STAGE2_ACCOUNT_PRIVACY_DECISIONS.md` **§29-1a** 다.
⏭ **3번 본인확인기관 위탁 — APP-5 로 이연**(2026-09-05 사용자 결정 · 위 문단).
✅ **6번 관리자 열람 감사기록 — 닫혔다**(2026-09-05 · §29-1c ㉨·㉩). **접속기록 2년 고정**이고
방침의 **「안전성 확보조치」 절**에 적는다. 사실조사는 §29-3a(고시 제8조 원문 · 시행령 제19조 ·
실제 서비스 둘). ⛔ **2년은 하한(1년)이 아니라 「전환 사건을 없애는 값」으로 골랐다.**
✅ **광고 식별자도 닫혔다**(2026-09-03 · ㉧) — 동의하면 개인맞춤형, 그 밖에는 비개인맞춤형.
✅ **연령 미달자 처리도 닫혔다**(2026-09-03 · ㉦) — 만 14세 미만은 막고 **아무것도 남기지 않는다**.
✅ 처리 근거와 보유기간은 **개정으로 닫혔다** — 받지 않는 값은 근거를 정할 대상이 없다.
✅ **6번의 사실조사도 저장소에 있다**(§29-3a) — 고시 제8조 원문 · 시행령 제19조(고유식별정보)

✅ **방침 개정 초안도 적었다**(§29-7). ⛔ **찍지 않는다** — 29-2 표가 **이번에 더하는 항목**

방침에도 이미 적혀 있다. **없는 광고를 미리 적지 않는다**는 §29-3 4번의 규칙을 본인확인에도

⛔ **초안이 나가는 조건은 단계 이름이 아니다** — **`production` 에서 본인확인이 켜져 실제 사람의
값을 받기 직전**이다(§29-7 ㄱ · 2026-09-05 Codex 독립 검토 5). **PWA-4·APP-2 의 본인확인은
mock/sandbox** 라 그때 찍어도 「받습니다」가 거짓이다.

「원본만 고치고 stamp 를 안 돌린 상태」를 실패로 잡는다.
⚠️ **「도메인 확보 뒤 stamp 한다」(R4)는 끝난 지시다** — 2026-09-04 에 11차를 찍고 배포했다.

불가하여 컬럼만 있고 값이 공백**이다(`collectionDb` 로 구분).
⚠️ **호출 시 `keyword` 는 빈 값이라도 반드시 붙인다**(공식 주의사항).
⛔ **신청은 「통합 수어정보」 하나면 된다** — 일상생활·전문용어·문화정보가 그 안에 있다.

⛔ **정정 — 위 「새로 생긴 길」은 새 길이 아니었다(2026-09-03, 같은 날 발견).**
**이 저장소는 이미 그 길 위에 있다.** 사용자가 지적해서 과거 기록을 뒤져 확인했다:
- `docs/API_KEY_GUIDE.md` 가 **culture.go.kr 활용신청 절차와 서비스키 수령**(`data@kcisa.kr`
  메일)을 이미 적어 뒀고, 엔드포인트는 **`api.kcisa.kr/openapi/service/rest/meta13/getCTE01701`**
  (일상생활 수어)다. ⛔ **data.go.kr 일반 인증키가 아니다** — 그 문서가 그 구분까지 적어 뒀다.
- 같은 문서의 응답 매핑표에 **`signImages`(쉼표구분) → `media.src[]`** 가 **이미 있다.**
- 같은 문서 끝에 **「데이터 라이선스: 일상생활 수어(국립국어원, 이용허락범위 제한 없음)」**이
  이미 적혀 있다.
- ⚠️ **실측(2026-09-03)**: `data/ksl-dict.json` = **3,622 표제어 · 이미지 URL 5,217개 ·
  호스트 100% `sldict.korean.go.kr`**.
  예: `https://sldict.korean.go.kr/multimedia/multimedia_files/convert/20160325/281631/MOV000277619_215X161.jpg`

⚠️ **그래서 R1 의 전제가 바뀐다.** 우리가 부르는 sldict 주소는 **긁어온 것이 아니라
「이용허락범위 제한 없음」인 API 가 `signImages` 로 돌려준 값**이다. 「CC BY-NC-ND 사이트의
이미지를 무단 핫링크한다」는 서술은 **이 경로에는 맞지 않는다.**

⛔ **그래도 R1 은 닫히지 않는다 — 남은 물음은 하나로 좁혀졌다:**
- **API 의 「이용허락범위 제한 없음」이 그 URL 이 가리키는 이미지 파일 자체에도 미치는가.**
  API 가 준 것은 **메타데이터와 경로**이고, 그 경로가 가리키는 사이트의 푸터는 여전히
  **CC BY-NC-ND** 다. ⚠️ **이 구분이 광고(㉧)와 우리 origin 복제(오프라인) 둘 다를 가른다.**
  ⛔ **Claude 는 이 해석을 판정하지 않는다** — 국립국어원에 물어야 할 것은 이제 이 한 문장이다.
- ⚠️ **업그레이드 여지**: 지금 쓰는 것은 **일상생활 수어 하나**(3,622)다. **「통합 수어정보」**
  (`api.kcisa.kr/API_CNV_054/request`)는 **일상생활 + 전문용어 + 문화정보**를 한 번에 주고
  2025-04-25 에 `signImages`·`signDescription` 이 추가됐다 — **전문용어 수어의 이미지가 는다.**
  (문화정보 수어는 국립국어원 미제공이라 값이 공백이다.)
- **「이용허락범위 제한 없음」이 이미지 파일 자체에도 적용되는지.** 데이터셋의 이용 조건과
  그 안에 담긴 개별 저작물의 조건은 다를 수 있다.
- **운영단계 승인.** 개발단계는 자동승인이지만 **운영단계는 심의승인**이다.
- **핫링크와 API 는 다른 행위다.** 지금 우리는 `sldict` 이미지를 **직접 핫링크**하고 있고,
  그 행위에 적용되는 것은 여전히 **CC BY-NC-ND** 다. API 로 갈아타야 조건이 바뀐다.
- ⛔ **다른 앱이 그렇게 하고 있다는 사실은 우리의 근거가 아니다** — 이 문서가 바로 위에서
  적은 원칙이다. 우리 이름으로 신청해서 우리 승인을 받아야 한다.

**그래서 R1 의 갈래가 넷이 됐다**: ① 오픈API 로 갈아탄다(**새로 생긴 유력안**) ②
별도 이용허락을 받는다 ③ 그림을 자체 제작한다 ④ 광고를 뺀다.
