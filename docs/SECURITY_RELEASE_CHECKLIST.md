## 미해결 — 왜 아직인가

### ✅ H1·H2 는 2026-08-11 에 해결됐다 (아래는 기록)
D1 이전과 쿠키 세션 전환을 **한 커밋에서** 했다. 나눠서 하면 쿠키만 먼저 나가 CSRF 공격면을
새로 열고 얻는 게 없기 때문이다. 자세한 절차·롤백은 [`D1_MIGRATION.md`](D1_MIGRATION.md).

#### H1. 친구·세션·삭제의 원자성 (D1 이전)
KV 에는 트랜잭션이 없다. 수락은 두 사람의 레코드에 **두 번 쓰기**라 첫 쓰기만 성공하면 반쪽이 남는다.
- **지금 막아 둔 것**: 반쪽 상태에서 **양쪽 다 접근이 막힌다**(P0-1). 즉 *권한이 새는 방향*은 닫혔다.
- **남은 것**: 목록에 이름만 남는 표시 불일치. 방침에도 그대로 적어 두었다.
- **최종 해결**: 관계 행 하나(`friendships`)를 D1 트랜잭션으로 다루기. 로컬 스키마·마이그레이션 작성은
  승인됐으나 **D1 리소스 생성과 Production 바인딩은 사용자 승인 대상**이라 아직 안 만들었다.
- ⚠️ 이전 시점의 KV 실측: **계정 1개, 친구 레코드 0개.** 지금 옮기면 사실상 공짜다. 사용자가 늘면 비싸진다.

### H2. 세션을 HttpOnly 쿠키 + 서버 세대(session_version)로
- **지금**: `localStorage` 의 Bearer 토큰. 토큰 앞부분이 내부 uid(무작위)라 **제공자 번호는 안 샌다**(P1-3).
- **남은 것**: ① 토큰이 완전 무작위가 아니다 ② 로그아웃이 `KV.list` 에 기대는데 최종 일관성 때문에
  **다른 기기가 60초 안에 만든 세션**은 못 지운다.
- **왜 안 했나**: `session_version` 을 KV 에 두면 그 읽기도 같은 최종 일관성을 져서 **창이 안 닫힌 채
  요청마다 KV 읽기만 하나 는다.** 쿠키 전환은 지금 원천적으로 불가능한 CSRF 공격면을 새로 여는 일이라
  (지금은 Bearer 라 CSRF 가 성립하지 않는다) D1 이전과 **같은 커밋에서** 해야 값이 있다.

### H3. 실제 레이트리밋 — **부분 해결. 볼류메트릭 방어는 여전히 없다**
> ⚠️ 이 절의 제목은 오래 "유일한 미해결 High"였고, 같은 문서 다른 곳은 "8/8 해결"이라 적혀 있었다.
> 둘 다 정확하지 않다. **지금 사실은 이렇다: 느린 남용은 막는다. 볼류메트릭은 못 막는다.**

- **확인된 사실**: Cloudflare **Rate Limiting 바인딩은 Pages Functions 에서 못 쓴다**(지원 바인딩 목록에 없음).
- **KV 카운터는 답이 아니었다**: 무료 플랜 하루 1,000 writes — 리미터 자체가 서비스 거부 수단이 된다.
  **D1 로 옮기면서 이 판단이 뒤집혔다**(하루 10만 writes). 그래서 지금은 D1 카운터가 **실제로 막는다.**
- **지금 있는 것**(`test-friends` 84~88·89~95):
  - `login` 10회/분(**세션이 생기는 자리만** — H7), `friends`(초대 코드) 20회/분,
    `rotate`(초대 링크 재발급) 5회/분(H6), `write` 120회/분. 창은 60초 고정.
  - 버킷 키는 **`RL_KEY` HMAC** 이다(H4). 키가 없으면 세지 않고 `/ready` 가 503 이다.
  - **한도에 닿으면 카운터를 더 갱신하지 않는다.** 안 그러면 공격자가 429 를 받으면서 우리 D1
    쓰기 할당량을 태울 수 있고, 그게 바닥나면 **정상 사용자의 단어장 저장이 먼저 죽는다.**
  - **실제로 있는 라우트에만 건다.** 없는 경로 POST 로는 카운터 행을 만들 수 없다.
  - 로그인 왕복은 `login` 버킷 **하나**로 센다(전에는 공통 `auth` 와 이중 집계였다 — 한도는 절반,
    쓰기는 두 배였고, `auth` 는 RL_MAX 에 없어 write 기본값 120 이 적용돼 **한 번도 먼저 막은 적이 없다**).
    **시작(`/login`)은 세지 않는다** — 세션도 DB 행도 안 만드는 자리다(H7).
  - ⛔ **당시 사실(2026-08-16~08-20).** 「리미터가 고장 나면 통과시킨다(fail-open, D1·바인딩 양쪽)」이
    그때의 판단이었다. **2026-08-22 에 뒤집혔다**(위협 52): 셀 수 없는 상태로 계정 경로를 여는 것은
    방어가 아니다 — 지금은 503 이다.
- **이것으로 막지 못하는 것 — 분명히 적어 둔다**:
  - **볼류메트릭 공격.** 요청이 우리 Function 까지 도달한 뒤에 세므로, 초당 수천 건이면 카운터가
    막아도 실행 비용은 이미 발생한다. 엣지에서 끊는 WAF 만이 이걸 막는다.
  - **위조 Origin.** 브라우저가 아닌 클라이언트는 허용된 Origin 문자열을 그대로 넣을 수 있다.
    Origin 검사는 CSRF 방어이지 남용 방어가 아니다.
  - ~~**IP 키의 되돌림.**~~ **해결(2026-08-16, H4).** 아래 참조.
- 실효가 있는 개별 상한들도 그대로다(친구 50명, 본문 8KB, OAuth 외부 호출 10초 타임아웃).
- **실제로 켜는 길 — 둘 다 코드가 아니다**:
  1. **커스텀 도메인을 붙이고 WAF 레이트리밋 규칙** ← 권장. `*.pages.dev` 는 Cloudflare 소유 존이라
     대시보드에서 규칙을 못 건다. **엣지 캐시 퍼지도 같은 조건이라 도메인 하나로 둘이 같이 풀린다.**
  2. API 를 Worker 로 되돌리고 `ratelimits` 바인딩 → 앱과 origin 이 갈려 CSP·쿠키·네이버 조건을
     전부 되돌려야 한다. 값보다 대가가 크다.

### H4. 레이트리밋 키 — 평문 해시에서 **비밀키 HMAC** 으로 (해결 2026-08-16)
- **무엇이 문제였나**: 키가 `SHA-256(용도|IP|창)` 이었다. IPv4 는 경우의 수가 43억뿐이라
  전부 넣어 보면 풀린다 — **실측에서 `/24` 대역만 대입해 43회 만에 원본 IP 가 나왔다.**
  `rate_limits` 를 읽을 수 있는 사람은 "누가 언제 우리 서비스에 왔나"를 복원할 수 있었다.
- **무엇이 바뀌었나**: `RL_KEY` 시크릿을 섞은 HMAC-SHA256 이다(`rlBucket`). 키를 모르면
  **넣어 볼 값 자체를 만들 수 없다.** `test-friends` 116~118 이 "평문 해시가 아님"을 직접 잰다.
- **`RL_KEY` 는 있어야 하는 값이다**: 없으면 `/ready` 가 503(`configReady:false`)이고
  리미터는 **세지 않고, 계정 경로를 열지도 않는다**(⛔ 2026-08-22 정정 · 위협 52 — 그전에는
  fail-open 이었다). 평문 해시로 되돌아가지 않는 이유는 조용히 약한 쪽으로
  도는 것이 가장 나쁘기 때문이다 — 아무도 못 알아채고 방침만 거짓말이 된다. `test-friends` 119~120.
- ✅ **production 등록 완료 2026-08-17.** 같은 날 라이브 실측에서 `/api/cb/kakao` 12회 중
  11번째부터 429 였고, 카운터는 11 에서 멈췄다(증폭 방어도 동작).
  ⚠️ **preview 환경에는 아직 없다** — OAuth 를 켜는 날 같이 넣는다. 안 넣으면 `/ready` 가 503 이라 드러난다.
- `privacy.html` 의 문구를 사실에 맞췄다("비밀키를 섞어 만들어 키를 모르면 되찾을 수 없습니다").
  네이버 검수 자료(`brand/NAVER-REVIEW.md`)에 같은 문단이 있으면 함께 고칠 것.

### H5. 계정 삭제 원자성 (해결 2026-08-16)
- **무엇이 문제였나**: `killSessions()` 다음 `DELETE FROM users`, **두 작업**이었다.
  두 번째가 실패했을 때를 주입해 재현했더니 — 500 이 나가고, 세대는 이미 올라가 **사용자는
  그 자리에서 로그아웃되며**, `users`·`books`·`friendships`·`invite_codes` 가 **전부 남았다.**
  그래서 "계정을 지우지 못했어요"를 본 사람의 **별명과 단어 개수가 친구에게 계속 보였고**,
  다시 로그인하기 전에는 재시도할 방법조차 없었다.
- **무엇이 바뀌었나**: `DELETE FROM users` **한 문장**이다. 한 문장은 그 자체로 원자적이라
  중간 상태가 존재할 수 없고, `whoAmI` 가 `JOIN users` 라 행이 사라지는 순간 모든 세션이 죽는다
  (세대 올리기는 로그아웃에만 남았다). 실패하면 아무것도 안 지워지고 **세션이 살아 있어
  그 화면에서 다시 누르면 된다.** `test-friends` 124~129.
- **누락 방지**: `users` 를 참조하는 모든 테이블이 `ON DELETE CASCADE` 인지 스키마를 훑어 확인하고,
  실제로 지워지는지도 한 번 돌려 본다(`test-migrations` 6~7). 사람이 기억해야 도는 규칙 대신
  검사가 깨진다. 로컬 D1 `PRAGMA foreign_keys` = 1 확인. **원격 D1 실측은 못 했다.**

### H6. 초대 코드 — 동시성과 쓰기 증폭 (해결 2026-08-16)

  탭은 이미 죽은 코드를 쥐고** 그 링크를 남에게 보냈다. 이제 충돌이 "누가 이미 만들었다"는

- **폐기 행을 회전할 때 함께 치운다**: 지우는 자리가 어디에도 없어 영구히 쌓였다. `test-friends` 112~115.
- ✅ **원격 D1 적용 완료 2026-08-17.** 중복 활성 코드가 이미 있는 DB 에서도 통과하도록 정리 문장을

### H7. 로그인 한도 — 문서가 말한 10회를 실제 10회로 (해결 2026-08-16)
`/login`(시작)·`/cb`·`/exchange` 가 같은 `login` 버킷을 써서, 한 번의 로그인이 두 자리를 지나
**한도 10 이 실제로는 완전한 로그인 5회**였다(실측). 공유 IP(회사·학교·모바일 CGNAT)에서는
그 5회를 건물 하나가 나눠 쓴다. 이제 **세션이 실제로 생기는 자리**(`/cb`·`/exchange`)에만 건다 —
`/login` 은 302 하나와 서명 하나이고 세션도 DB 행도 안 만든다. `test-friends` 121~123.

### H8. OAuth 제공자 응답 크기 상한 (해결 2026-08-16)
`JSON.parse(await r.text())` 에 크기 상한이 없어 **남의 서버가 우리 Worker 메모리를 정했다**
(무료 128MB, 로그인 한 번에 두 번 호출). 실측에서 1MB 토큰 응답이 그대로 적재되고 **로그인이
성공했다.** 이제 64KB 다 — 실제 정상 응답 중 가장 큰 구글 토큰(id_token 포함)이 2~4KB 라 16배 여유다.
Content-Type 은 **일부러 안 본다**(실제 판정은 `JSON.parse` 가 하고, 허용 목록은 제공자가
`text/plain` 으로 바꾸는 날 로그인을 죽인다 — `test-friends` 104 가 이 판단을 잠근다).
제공자 오류 문자열도 80자로 자른다. `test-friends` 101~106.

### H9. 서비스워커 activate — 청소 실패가 제어권 인수를 막았다 (해결 2026-08-16)
`Promise.all` 이라 옛 캐시 하나를 못 지우면 그 거절이 `clients.claim()` 까지 건너뛰었다 —
**새 세대가 활성인데 떠 있는 탭은 계속 옛 세대**가 된다. 이미 겪은 「세대 혼합」의 재발 경로다.
`allSettled` 로 바꿔 청소가 실패해도 제어권은 넘겨받는다. `test-sw` 11~12.
> ⚠️ 함께 확인하고 **안 고친 것**: `self.skipWaiting()` 이 install 의 `waitUntil()` 밖에 있는 것은
> **지금이 맞다.** 그 Promise 는 활성화될 때 풀리므로 install 이 그것을 기다리면 서로를 기다린다.
> 선캐시(`addAll`) 실패로 install 이 거절되는 것도 맞다 — 반쪽 세대보다 옛 세대가 낫다(`test-sw` 11).

### 미검증 수어 — 알고 안 한 것 하나
데이터에 `verificationStatus` 필드를 **일부러 안 만들었다.** 그 값의 출처가 결국 `ksl-pins.json`
(사람이 고른 수형)이라, 필드로 복사해 두면 **진실이 둘**이 되어 갈라진다. 상태는 저장하는 것이 아니라
`unpinnedCandidates()` 한 함수가 계산하는 것으로 남기고, 대신 **실데이터 400건**에 대고
"출제된 것에는 미확정 부품이 없다"를 잠갔다(`test-compounds`).
⚠️ **카피에 "정확한 수어"·"검증된"을 쓰지 않는다** — 합성 2,485 중 사람이 확인한 건 12건이다.

## 방침 대조표 — `privacy.html` 이 코드와 맞는가

| 방침이 말하는 것 | 코드 | 상태 |
|---|---|---|
| 제공자 회원번호는 짝짓는 곳에만 저장, 친구·화면에 안 나온다 | `users.provider_subject` (그 행 밖으로 안 나감) | ✅ `test-friends` 43~46 |
| 세션은 **완전 무작위** · 계정 번호도 안 들어 있다 | `mkToken()` = 무작위 32바이트 | ✅ 45 |
| 기기에는 **HttpOnly 쿠키**, 서버에는 **해시만** | `setCookie()` · `sessions.token_hash` | ✅ 26 + 실기(Bearer 401) |
| 계정 삭제 시 제공자 연결까지 지워진다 | `DELETE FROM users` + CASCADE | ✅ 12 |
| 끊으면 **양쪽 모두에서** 사라진다 · 한쪽만 남는 상태가 없다 | 관계 = `friendships` 행 하나 | ✅ 5·10·61~66 |
| **모든 기기에서 즉시** 로그인이 풀린다 | `session_version + 1` (목록을 안 훑는다) | ✅ 28~30 |
| 보유 기간 · 국외이전 7항목 · 처리 근거 | — | ✅ 표로 명시 |
| 만 14세 이상 · 기술적 확인 수단 없음 | 생년월일 미수집 | ✅ 약속임을 명시 |
| **수락 전에도 별명이 보인다** | `briefRow(…, false)` 가 pending 에도 `name` 을 싣는다 | ✅ 2026-08-14 에 **방침을 코드에 맞췄다**(아래 참고) |
| 수락 전에는 단어·개수가 안 보인다 | pending 응답에 `count`·`words` 없음 | ✅ `test-friends` 4b·5 |
| 세션은 180일 뒤 만료되고 **만료된 기록은 지워진다** | `newSession` 이 만료·폐기 행을 지운다 | ✅ `test-friends` 80·81 |
| 남용 방어로 **횟수만** 센다 · IP·계정번호 원문 미저장 | `rate_limits.bucket` = HMAC(RL_KEY, 용도\|주체\|창) | ✅ `test-friends` 88·116~118 |
| 요약값에 **비밀키를 섞어** 키를 모르면 IP·계정번호를 되찾을 수 없다 | `rlBucket()` (HMAC-SHA256) | ✅ 116~117. `RL_KEY` 는 2026-08-17 production 등록. 키가 없는 환경에서는 리미터가 세지 않는다(`/ready` 503) |
| 계정 삭제가 **모든 연결 데이터**를 지운다 | `DELETE FROM users` 한 문장 + CASCADE 전수 검사 | ✅ `test-friends` 124~129 · `test-migrations` 6~7 |

> ⚠️ **「친구로 맺어진 상대에게만 별명이 보인다」는 문장은 틀린 문장이었다.** 서버는 처음부터
> 수락 전 요청 목록에도 별명을 실어 보내고 있었다. 고르는 길이 둘이었다 —
> ① 응답에서 별명을 빼거나 ② 방침을 사실에 맞추거나.
> **②를 골랐다.** ①이 개인정보 최소화에는 맞지만, 별명을 빼면 받은 요청 목록에
> 「별명을 안 지은 사람」만 줄지어 남아서 **연인이 보낸 요청인지 링크를 주운 낯선 사람인지
> 가릴 단서가 하나도 없어진다.** 그러면 아무나 수락하게 되고, 그 피해가 별명 노출보다 크다.
> 별명은 제공자에게 받은 실명이 아니라 사용자가 직접 지은 아무 말이라는 점도 함께 봤다.
> **이 판단은 되돌릴 수 있다** — ①로 가려면 `worker/index.js` 의 `briefRow(…, false)` 에서
> `name` 을 빼고 `privacy.html` 과 이 표를 같이 고치면 된다.

> ⚠️ 방침에서 **「드물게 목록에 이름만 남을 수 있다」와 「1분 이내 새 세션은 늦을 수 있다」를 지웠다.**
> 둘 다 KV 의 한계를 정직하게 적어 둔 문장이었는데, D1 으로 옮기면서 **사실이 아니게 됐다.**
> 한계가 사라지면 그 한계를 적은 문장도 같이 지워야 한다 — 안 지우면 이번엔 반대 방향으로 거짓말한다.

⚠️ **법률 검토는 아직 안 받았다.** 위 표는 *사실 대조*이지 법적 충분성 판정이 아니다.
**AI 는 이 판정을 하지 않는다**(`.claude/rules/privacy.md`). 아래는 검토자에게 그대로 넘길 질문이다.

| # | 물어볼 것 | 지금 상태(사실) |
|---|---|---|
| 1 | **동의 방식** — "로그인 버튼을 누른 것"을 개인정보 수집·이용 동의로 볼 수 있나. 별도 체크박스가 필요한가 | 로그인 화면에 방침 링크만 있고 동의 체크박스는 없다 |
| 2 | **국외이전 동의** — Cloudflare(미국 포함)로 나가는 것에 별도 동의가 필요한가, 고지로 충분한가 | 방침에 항목·국가·시기·방법을 표로 고지. 별도 동의 절차 없음 |
| 3 | **만 14세 미만** — 확인 수단 없이 "만 14세 이상만"이라고 적어 두는 것으로 충분한가. 법정대리인 동의를 받아야 하나 | 생년월일을 안 받는다. 방침에 약속으로만 적혀 있다 |
| 4 | **접속 기록** — 남용 방어 카운터(해시+횟수, 몇 분 뒤 삭제)와 호스팅 사업자 로그가 수집 항목으로 고지되어야 하나 | 방침의 국외이전 표에 "접속 기록"으로 포함. 카운터는 2026-08-14 에 항목을 새로 적었다 |
| 5 | **파기** — "계정을 지울 때까지"라는 보유 기간과, 계정 삭제가 즉시 CASCADE 로 지우는 방식이 파기 규정에 맞나 | 지우면 그 자리에서 사라진다. 별도 보관 없음(결제·거래 기능 없음) |
| 6 | **별명 공개 범위** — 수락 전 요청 단계에서 별명이 상대에게 보이는 것을 방침 고지만으로 다룰 수 있나 | 2026-08-14 부터 방침에 명시. 위 표 참고 |

네이버 검수에 낸 문서이므로 **문구를 고치면 검수 자료도 같이 고친다**(`brand/NAVER-REVIEW.md`).

## 배포 전 (매번)

```bash
npm test          # 전부 통과해야 한다 (test-friends 75 · hash · sw · dist 포함)
npm audit         # 0 vulnerabilities
npm run build     # dist/ 재생성
```

## 배포

```bash
npm test && npm run build
npx wrangler pages deploy dist --project-name shhh-app --branch main
```

⚠️ **`--commit-dirty=true` 를 쓰지 않는다**(`CLAUDE.md` §9 의 절대 규칙). 예전 이 문서에는 그 플래그가
적혀 있었다 — 그러면 커밋되지 않은 작업 트리가 프로덕션으로 나가고, **나중에 배포된 것이 어느 커밋인지
알 방법이 사라진다.** 작업 트리가 더럽다면 배포가 아니라 커밋이 먼저다.

⚠️ **`--branch main` 을 빼면 프리뷰로 간다.** git 브랜치가 `cf-pages` 라 그렇다 — 한 번 겪었다.
프로덕션인지는 `npx wrangler pages deployment list --project-name shhh-app` 의 `Environment` 열로 확인한다.

## 배포 후 검증

```bash
# ⚠️ 검증 명령에 함정이 셋 있다. 하나라도 빠지면 **멀쩡한 배포를 실패로 오진한다**(전부 겪었다):
#    ① `?cb=` — 안 붙이면 엣지 캐시가 옛 파일을 준다.
#    ② `-L`   — Pages 는 `/privacy.html` 을 `/privacy` 로 **308** 보낸다. 안 따라가면 본문이 빈다.
#    ③ 상태코드가 아니라 **Content-Type** 을 본다 — 없는 경로에 index.html 을 200 으로 준다.
for u in /CLAUDE.md /worker/index.js /wrangler.jsonc /package.json /scripts/test-friends.mjs; do
  curl -sL -o /dev/null -w "$u %{content_type}\n" "https://shhh-app.pages.dev$u?cb=$RANDOM$RANDOM"
done
#   → 전부 text/html 이어야 한다 (= 파일이 없어서 index.html 로 떨어진 것)

# 방침이 실제로 갱신됐는지 (-L 없으면 308 만 받는다)
curl -sL "https://shhh-app.pages.dev/privacy.html?cb=$RANDOM$RANDOM" | grep -oE "마지막 수정: [0-9-]+"

curl -s  https://shhh-app.pages.dev/api/health     # {"ok":true,"ready":?,"providers":[...]}
curl -sI https://shhh-app.pages.dev/api/ready | head -1   # 200 이어야 정상
curl -sI https://shhh-app.pages.dev/ | grep -i content-security-policy
for p in kakao naver google; do
  curl -s -o /dev/null -w "$p %{http_code}\n" "https://shhh-app.pages.dev/api/login/$p"   # 302 = 정상, 503 = 키 없음
done
```

⚠️ **세 번은 재라**(함정 48·57). 배포 직후 몇 초는 옛 코드가 응답하고, 한 번만 재면 "고쳤는데 안 먹힌다"고 오진한다.


## OAuth — 사람이 해야 하는 것

**비밀값은 사람이 넣고 사람이 보관한다.** 값을 문서·로그·명령 출력에 남기지 않는다.

```bash
cd ~/Desktop/claude/shhh\!
for k in KAKAO_ID KAKAO_SECRET NAVER_ID NAVER_SECRET GOOGLE_ID GOOGLE_SECRET; do
  npx wrangler pages secret put $k --project-name shhh-app
done
npx wrangler pages secret list --project-name shhh-app     # 이름만 보인다
```

| 이름 | 없으면 | 어디에 |
|---|---|---|
| `STATE_KEY` | **로그인 전체가 503** (실패-닫힘) | 시크릿 |
| `KAKAO_ID`/`SECRET`, `NAVER_ID`/`SECRET`, `GOOGLE_ID`/`SECRET` | 그 제공자만 버튼이 안 뜬다 | 시크릿 |
| `MASTER_UIDS` | 아무도 마스터가 아니다(안전한 기본값) | 시크릿 · **값이 내부 uid 로 바뀌었다** |
| `APP_ORIGIN`, `APP_URL` | 복귀 주소 검증이 안 선다 | `wrangler.jsonc` |
| `DEV_ORIGINS` | (운영에는 넣지 않는다) | 개발 Worker 전용 |

⚠️ **Preview 환경은 시크릿이 따로다.** 프로덕션에 넣어도 프리뷰 배포에서는 로그인이 503 이다.
⚠️ 콜백 URL 은 `worker/SETUP.md` 그대로. **옛 `workers.dev` 리디렉션 URI 는 콘솔에서 지울 것** —
문이 둘이면 잠금은 약한 쪽을 따른다.

## 엣지 캐시 (미해결, 알고 있는 것)

`shhh-app.pages.dev/CLAUDE.md` 를 **쿼리 없이** 부르면 아직 옛 파일이 온다
(`cf-cache-status: HIT`, `s-maxage=604800` = 7일). 배포 자체는 깨끗하다(`?cb=` 로 확인).
- 심각도 낮음: 그 내용은 **공개 레포에 그대로 있고** 비밀값이 없다.
- `*.pages.dev` 는 Cloudflare 소유 존이라 사용자가 퍼지할 수 없다. **커스텀 도메인을 붙이면 풀린다**
  (WAF 레이트리밋과 같은 조건).
