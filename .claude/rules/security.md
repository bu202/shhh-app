# 인증·데이터 보안 규칙

## 변경 전

- `CLAUDE.md`의 열린 P0/P1 항목과 현재 코드를 대조한다. 과거 문서의 완료 표시를 근거로 삼지 않는다.
- 인증 흐름은 `로그인 시작 → 제공자 → 콜백 → 세션 생성 → 클라이언트 상태 → 첫 동기화` 전체를 추적한다.
- 정상 경로 테스트만 보지 말고 공격자가 만든 링크, 오래된 탭, 계정 교체, 동시 요청을 포함한다.

## 지켜야 할 보안 불변식

1. OAuth 요청을 시작한 브라우저와 콜백을 **서버에서** 결속한다. 클라이언트 localStorage nonce만 보안 경계로 쓰지 않는다.
2. 결속 검증에 실패하면 OAuth code 교환 또는 세션 쿠키 설정 전에 거부한다. 이미 세션이 생긴 실패 경로가 있으면 즉시 폐기한다.
3. 계정 A의 단어장·별명·book version·친구 목록·초대 코드는 계정 B로 전파되지 않는다.
4. 동기화의 승자를 클라이언트 벽시계로 정하지 않는다. 서버 version과 명시적인 dirty/base 상태로 충돌을 감지한다.
5. 친구 관계는 사용자 쌍당 논리적으로 하나다. A→B/B→A 경합과 재시도를 DB 제약과 원자적 연산으로 처리한다.
6. 인증된 상태 변경 요청은 허용 origin을 명확히 확인한다. 브라우저 PWA 요청에서 Origin 부재를 자동 허용하지 않는다.
7. 세션은 원문을 서버에 저장하지 않고 만료·전체 로그아웃·계정 삭제가 즉시 반영돼야 한다.
8. 공개 베타 전 로그인·친구·쓰기 경로에 실효성 있는 남용 방어를 둔다. 존재하지만 비활성인 이음새를 rate limiting 완료로 세지 않는다.
9. readiness는 바인딩 존재만 보지 않고 실제 DB 질의와 필요한 OAuth ID/secret 쌍을 확인한다. 값 자체는 노출하지 않는다.
10. 에러 응답과 로그에는 provider subject, 세션, 초대 코드, 원본 경로의 개인 ID를 남기지 않는다.

## 최소 회귀 시나리오

- 공격자 콜백 링크를 이미 로그인한 피해자가 여는 경우
- nonce/state가 없거나 틀리거나 재사용된 경우
- A 로그인 → 로컬 변경 → 로그아웃 → B 로그인 → 첫 동기화와 초대 링크 공유
- 기기 시계를 미래와 과거로 바꾼 두 클라이언트의 GET→PUT
- A→B와 B→A 친구 요청의 동시 실행과 재시도
- Origin 없음, 허용 origin, 외부 origin의 모든 상태 변경 메서드
- 로그아웃·계정 삭제 후 기존 모든 세션의 접근

## 의사결정 경계

인증 방식, 계정 데이터 삭제 범위, 충돌 병합, DB 스키마는 구현 전에 최소 변경안과 구조적 해결안을 비교해
사용자 승인을 받는다. 테스트 추가와 읽기 전용 재현은 먼저 진행할 수 있다.
