# 개인정보·정책 일치 규칙

- 법률 판단과 코드 사실 대조를 구분한다. 법률 자문을 받지 않은 항목을 “법적으로 완료”라고 쓰지 않는다.
- 수집하는 값, 저장 위치, 보유 기간, 공개 상대, 삭제 효과를 코드와 방침에서 같은 의미로 유지한다.
- 로그인하지 않은 상태의 health 요청 등 실제 네트워크 호출도 방침의 “전송하지 않음” 주장과 대조한다.
- 친구 요청 단계와 수락 후에 보이는 별명·단어장·개수 정보를 각각 명시하고 최소한만 응답한다.
- 계정 삭제가 모든 세션과 연관 데이터를 실제로 제거하는지 DB에서 검증한다. 화면 문구만으로 완료하지 않는다.
- 만 14세 미만을 허용할지, 배제할지, 법정대리인 동의를 받을지는 사용자가 법률 검토를 바탕으로 결정한다.
- OAuth 진행을 개인정보 동의로 간주하는 방식은 공개 베타 전에 별도 검토한다.
- 사용자 UID, 복구 링크, 세션, OAuth code, 실제 별명은 추적되는 문서·로그·테스트 fixture에 넣지 않는다.
- 개인정보 동작을 바꾸면 코드, `privacy.html`, 제공자 검수 자료를 같은 변경 단위에서 갱신한다.

## 정책 이벤트와 복원 불변식 (2026-08-17 확정)

- **고지, 약관 수락, 연령 진술, 개인정보 동의를 같은 action 으로 기록하지 않는다.**
  법적으로 다른 행위다. 하나로 뭉치면 받지 않은 동의를 받았다고 적는 것이 된다.
- **법적 근거가 확정되기 전에는 `privacy/accepted` 를 만들지 않는다.** 처리 근거가 계약 이행이면
  동의 체크박스가 오히려 사용자를 오도한다.
- 정책 버전은 손으로 적는 번호가 아니라 **실제 불변 문서의 내용 해시**로 검증한다.
  내용이 바뀌었는데 manifest 가 그대로면 테스트가 실패해야 한다.
- **Time Travel 또는 수동 백업 복원 전후에 확정된 삭제 표식을 재적용한다.**
  복원은 탈퇴 계정을 되살린다. 절차는 `docs/STAGE2_ACCOUNT_PRIVACY_DECISIONS.md` §9.
- **복원으로 탈퇴 계정이 부활한 상태에서 서비스를 재개하지 않는다.** 재삭제와 CASCADE 결과를
  확인한 뒤에만 연다.
